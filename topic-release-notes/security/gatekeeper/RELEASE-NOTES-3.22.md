# gatekeeper v3.22 Release Notes

Source: [v3.22.0](https://github.com/open-policy-agent/gatekeeper/releases/tag/v3.22.0)

## 🚀 Notable Changes

- ✅ **`sync-vap-enforcement-scope` now enabled by default:** The [flag](https://open-policy-agent.github.io/gatekeeper/website/docs/next/validating-admission-policy) for syncing ValidatingAdmissionPolicy enforcement scope is now `true` by default, ensuring VAP resources reflect constraint enforcement actions out of the box ([#4332](https://github.com/open-policy-agent/gatekeeper/pull/4332)).
- 🏷️ **Namespace support for CEL and Rego engines:** CEL expressions can now access `namespaceObject` and Rego policies can access `input.namespace` for namespace-scoped policy decisions during both admission and audit ([#4285](https://github.com/open-policy-agent/gatekeeper/pull/4285))
- ⚡ **`gator bench` — policy performance benchmarking:** New CLI command to benchmark Rego and CEL engines with latency percentiles, throughput metrics, memory profiling, concurrent load testing, and baseline comparison for CI/CD regression detection ([#4287](https://github.com/open-policy-agent/gatekeeper/pull/4287))
- 📋 **`gator policy` — brew-inspired policy management:** New CLI for discovering, installing, upgrading, and uninstalling policies from the gatekeeper-library with support for bundles (e.g., `pod-security-baseline`), enforcement overrides, and dry-run previews ([#4331](https://github.com/open-policy-agent/gatekeeper/pull/4331))
- 🔇 **Disable audit sidecar support:** Users who have their own log monitoring (e.g., OTel collector) can now disable the forced `fake-reader` sidecar when audit file-based logging is enabled ([#4280](https://github.com/open-policy-agent/gatekeeper/pull/4280))
- 🌐 **Out-of-cluster / remote cluster support:** New `--enable-remote-cluster` flag allows Gatekeeper to run outside the target cluster (e.g., nested/hosted control planes), fixing a crash when the Gatekeeper pod doesn't exist in the managed cluster ([#4368](https://github.com/open-policy-agent/gatekeeper/pull/4368))
- ⏱️ **External data provider timeout enforcement:** Mutation-path requests to external data providers now enforce the provider's configured timeout (default 5s), preventing unbounded requests that could outlive the webhook timeout and cause resource exhaustion ([#4351](https://github.com/open-policy-agent/gatekeeper/pull/4351))
