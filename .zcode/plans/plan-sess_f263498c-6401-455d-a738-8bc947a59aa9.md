### 阶段 1：物理重命名目录（`git mv`）

对 20 个目录执行 `git mv`：
```
git mv 集群基础 集群基础
git mv 工作负载 工作负载
... (共 20 个)
```
纯重命名，git 保留历史。

### 阶段 2：全库引用替换（Python 脚本，先 dry-run 后执行）

写一个 `scripts/_rename_domains.py` 一次性脚本，核心逻辑：

**A. 精确替换 20 个当前 slug**（最安全，占引用量 95%+）：
对每个 `domain-NN-slug` → 中文名，在所有 .md/.js/.py/.sh/.yml/.yaml/.json/.toml/Makefile 中做**全字符串替换**（exact match，非正则）。这会覆盖 wikilink、frontmatter sources、category、domain_link、正文路径、代码硬编码等所有形态。

**B. 碰撞隔离的旧编号处理**：
- 6 个碰撞编号（domain-10/16/17/18/19/20 作为旧引用）→ **不处理**（无法判断意图）
- 其余无歧义旧编号（domain-1~9, 11~15, 21~43 中的安全项）→ 按 43→20 映射表替换为新中文名
- 例外：scripts/ 下的 `generate-mocs.py`、`batch-fix-quality.py`、`enhance-cross-refs.py` 等含大量旧 domain-1-* 到 domain-40-* 映射的脚本——这些映射表本身是数据，整体替换会让旧映射表变成无意义的中文名混乱，**保留不动**（它们是历史维护脚本，已不再活跃使用）

**C. 明确排除的文件/目录**（绝不触碰）：
- `_archives/`（归档快照，历史记录）
- `web/visualizations/data.json`、`docs/visualizations/data.json`（用旧编号的独立可视化数据，scheme-3，与文件树无关）
- `.qoder/`、`.understand-anything/`、`.claude/`（IDE 缓存）
- 子串碰撞：`domain-java-kubernetes`、`domain-guide`、`domain-hd`、`domain-explorer` 等（通过 exact slug match 自动规避）

**dry-run**：先统计每类替换的影响（文件数、替换次数），打印供确认，再正式执行。

### 阶段 3：修复去前缀后的检测逻辑

**RUNTIME-critical（站点会崩）**：

1. **`web/src/lib/docs.js`**：
   - `inferCategory()`：`startsWith('domain-')` → 用新的 20 中文名集合 `DOMAIN_DIRS.has(parts[0])` 判断
   - `getDomainMeta()`：domainMap 的 20 个 key 全部改为中文名（值不变）
   - L48 根文件过滤：`startsWith('domain-')` → 改为允许中文名集合 或 调整逻辑（该过滤只影响根目录散落 md，重命名后需确认 concepts/entities 等仍正常）

2. **`.github/workflows/quality.yml`**：
   - L6 `paths: 'domain-*/**'` → 列出 20 个中文名 或 改用 `paths-ignore` 反向排除
   - L50/L94 `p.parts[0].startswith('domain-')` → `p.parts[0] in CHINESE_DOMAINS`（CONTENT 集合扩展）

**CI/构建脚本（不崩但失效）**：

3. **Makefile** L7-9：`故障诊断` → `故障诊断`
4. **`scripts/generate-readme-stats.sh`**：`domain-*` glob → 显式中文名列表 或 基于排除列表的 find
5. **`scripts/generate_indexes.py`**：DOMAINS 列表的 dirname 全部改中文名
6. **`scripts/generate-qa-corpus.py`**：CORE_DOMAINS + OUTPUT_DIR 改中文名
7. **`scripts/check-broken-links.sh`**、**`scripts/agent-corpus-quality-check.sh`**：`domain-*` glob 替换
8. **`_meta/corpus-config/scripts/enhance-metadata.py`**：INCLUDE_PATTERNS + detect_domain
9. 其他含 `startswith('domain-')` 的 Python 脚本（add-intent-queries.py、bulk_fill_summary...、evaluate_corpus_completeness.py 等）

**核心策略**：在 docs.js 导出一个 `DOMAIN_DIRS` 常量集合，各脚本各自维护一份同名列表（或读取一个共享配置），统一用集合判断替代前缀检测。

### 风险与缓解

| 风险 | 缓解 |
|---|---|
| exact-match 替换遗漏带后缀的引用（如 `domain-10-...-qa.yaml` 文件名） | 脚本同时处理文件名替换（含 QA corpus yaml 文件名） |
| 碰撞编号误替换 | 6 个碰撞编号硬编码为"不处理"白名单 |
| scripts/ 旧映射表被替换成无意义内容 | 这些脚本整体排除（或仅替换 20 个当前 slug，不动旧编号） |
| 替换产生新的子串碰撞 | 用完整 slug exact match，不用前缀正则 |
| 构建耗时超限 | 用部分构建验证逻辑正确性，完整构建留给 CI |

### 明确排除（不在范围）

- ❌ 不处理 scripts/ 中纯历史维护脚本（generate-mocs 等含旧 43-domain 映射的）
- ❌ 不改 QA corpus 数据内容中的旧路径（仅改文件名中的 slug）
