# 观众互动设计

> **目标**: 让观众从「听」变为「参与」, 提升发布会记忆点和后续转化

---

## 一、现场投票 (3 个技术话题)

### 工具

- **首选**: Slido (与 PPT 集成好, 支持词云)
- **备选**: Mentimeter (独立使用更灵活)

### 投票话题

| # | 话题 | 选项 | 时机 |
|---|------|------|------|
| 1 | 你在 K8s 运维中最头疼的问题是什么? | A. 问题排查耗时长 / B. 知识分散难找 / C. 新人上手慢 / D. 多云差异大 | 开场后 5 分钟 |
| 2 | 你目前获取 K8s 知识的主要方式? | A. 官方文档 / B. 搜索引擎 / C. 社区博客 / D. 公司内部 Wiki | 场景 2 演示后 |
| 3 | 你最希望 Agent 能帮你做什么? | A. 自动问题排查 / B. 生成运维 SOP / C. 多云配置对比 / D. 知识库检索 | 场景 4 演示后 |

### 执行流程

1. 主持人说 "请大家扫码投票, 结果会实时显示在大屏上"
2. PPT 切换到投票页面, 显示二维码 (Slido 自动生成)
3. 等待 30-45 秒, 主持人引导 "还有 10 秒"
4. 展示结果, 主持人点评: "看来 XX 是大家最头疼的, 这正是 kudig-database 要解决的"
5. 自然过渡到下一个演示场景

## 二、扫码体验: 现场试用 Agent

### 引导流程

1. **大屏展示二维码** (PPT 专用页)
   - 链接指向: `try.kudig.io` (或临时体验环境)
   - 二维码下方文字: "扫码即刻体验 K8s AI Agent"

2. **引导话术** (主持人):
   > "现在请大家拿出手机, 扫描大屏上的二维码。你将进入一个真实的 Agent 对话界面。
   > 试着问它一个你最近遇到的 K8s 问题, 看看它能不能帮你找到答案。"

3. **预设体验路径**:
   - 引导问题 1: "Pod 一直处于 Pending 状态, 怎么排查?"
   - 引导问题 2: "对比 AWS EKS 和阿里云 ACK 的节点升级策略"
   - 引导问题 3: "生成一份 etcd 备份恢复的 SOP"

4. **体验时间**: 3-5 分钟 (配合投票环节)

### 技术准备

- [ ] 体验环境提前 24h 部署, 压测通过
- [ ] 备用环境: 如主环境挂了, 切换到 backup URL
- [ ] 手机端 UI 适配测试 (iOS Safari / Android Chrome)
- [ ] 并发支持: 预估 200 人同时在线

## 三、实时问答 (预设引导性问题)

### 预设问题 (用于冷场时主持人自问自答)

| # | 问题 | 引导方向 |
|---|------|----------|
| 1 | "这个知识库和 ChatGPT 有什么区别?" | 强调: 专业领域 + 结构化 + 可执行, 不是通用大模型的泛泛而谈 |
| 2 | "知识库会持续更新吗? 怎么保证时效性?" | 引出: 开源社区贡献 + CNCF 版本跟踪 + 自动化更新机制 |
| 3 | "企业内部能用自己的知识训练吗?" | 引出: 支持私有部署 + 自定义 RAG + 企业知识融合 |
| 4 | "和直接搜 Google 比, 优势在哪?" | 引出: 结构化 > 碎片化, Agent 就绪 > 人工阅读, 可执行 > 纯理论 |
| 5 | "开源的话, 商业模式是什么?" | 引出: 开源知识库 + 商业 Agent 平台 + 企业级支持服务 |

### 问答执行策略

- 前 3 个问题由主持人主动提问, 邀请嘉宾回答
- 如果观众互动冷场, 主持人从预设问题中选取
- 如果观众互动热烈, 优先回答观众问题, 预设问题留作补充
- 每个问题控制在 2 分钟以内
