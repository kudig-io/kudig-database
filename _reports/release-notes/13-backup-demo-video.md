# 备用 Demo 录屏脚本

> **用途**: 发布会现场演示的备用录像, 以防现场演示出现网络/环境问题
> **总时长**: 8-10 分钟
> **录制工具**: OBS Studio (1080p, 30fps)

---

## 场景 1: 深度研究 — etcd 生产运维 (2 分钟)

### 录屏步骤

| 步骤 | 操作 | 时长 |
|------|------|------|
| 1 | 打开 Agent 对话界面, 光标停在输入框 | 5s |
| 2 | 输入: `我要深度研究 etcd 的生产运维, 包括架构原理、Raft 共识、备份恢复和性能调优` | 10s |
| 3 | Agent 输出, 镜头跟随滚动 | 60s |
| 4 | 高亮关键知识点: Raft 选举 / WAL 日志 / snapshot 策略 | 30s |
| 5 | 展示 Agent 引用的源文档列表 | 15s |

### 旁白

> "一个刚接手 etcd 运维的工程师, 只需要一句话, Agent 就能从 3,346 篇知识中精准提取 etcd 相关的 50+ 篇文档, 自动组织成从原理到实操的完整知识图谱。"

### 预期画面

- Agent 输出分 4 个板块: 架构原理 / Raft 共识 / 备份恢复 / 性能调优
- 每个板块有 3-5 个关键知识点 + 可点击的源文档链接
- 底部显示检索耗时 (预计 < 2s)

### 剪辑要点

- 输入时加速 2x, 输出时正常速度
- 关键知识点出现时加黄色高亮框
- 底部字幕: "深度研究模式 — 一句话构建完整知识图谱"

---

## 场景 2: 问题排查 — Pod CrashLoopBackOff (2.5 分钟)

### 录屏步骤

| 步骤 | 操作 | 时长 |
|------|------|------|
| 1 | 模拟终端, 展示 `kubectl get pods` 输出 (含 CrashLoopBackOff) | 10s |
| 2 | 切换到 Agent, 输入问题 + 粘贴日志片段 | 15s |
| 3 | Agent 分步排查输出 | 60s |
| 4 | 展示 Agent 给出的可执行命令 | 30s |
| 5 | 执行修复命令, Pod 恢复 Running | 25s |

### 旁白

> "这是 [[entities/kubernetes.md|k8s]] 运维最常见的问题之一。传统做法是 Google 搜半天, 翻阅十几篇博客。现在, Agent 会按照 23 个问题诊断场景的标准排查流程, 从日志分析到根因定位, 最后直接给你可执行的修复命令。"

### 预期画面

- 终端: `kubectl get pods -n production` 显示 1 个 CrashLoopBackOff
- Agent 输出结构化排查步骤: 日志分析 → 资源检查 → 配置校验 → 根因定位
- 最终给出 `kubectl edit` 或资源调整命令
- 执行后 Pod 状态变为 Running

### 剪辑要点

- 终端操作正常速度, 体现真实感
- Agent 排查步骤用箭头动画串联
- 修复成功时加绿色 ✓ 动画
- 底部字幕: "问题排查模式 — 23 个诊断场景覆盖 90% 生产问题"

## 场景 3: 可执行 SOP — etcd 备份恢复 (2 分钟)

### 录屏步骤

| 步骤 | 操作 | 时长 |
|------|------|------|
| 1 | Agent 输入: `执行 etcd 备份 SOP` | 5s |
| 2 | Agent 输出完整 SOP 步骤 | 40s |
| 3 | 展示关联的自动化脚本 | 20s |
| 4 | 点击脚本, 展示内容 | 20s |
| 5 | 模拟执行备份命令 | 20s |
| 6 | 展示备份文件生成成功 | 15s |

### 旁白

> "kudig-database 不只告诉你怎么做, 还提供可直接执行的 SOP 和脚本。18 个标准操作流程, 17 个配套脚本, 从备份恢复到集群升级, 一键调用。"

### 预期画面

- SOP 输出格式: 适用场景 → 前置检查 → 操作步骤 → 验证方法 → 回滚方案
- 脚本内容: 带注释的 bash 脚本, 含错误处理
- 执行输出: 备份文件路径 + 校验和

### 剪辑要点

- SOP 展开时用折叠动画
- 脚本高亮语法着色
- 执行成功加 "SOP 完成" 标签动画
- 底部字幕: "可执行 SOP — 从文档到脚本, 零手工编写"

## 场景 4: 速查卡 — 多云对比 (1.5 分钟)

### 录屏步骤

| 步骤 | 操作 | 时长 |
|------|------|------|
| 1 | Agent 输入: `对比 AWS EKS、阿里云 ACK 和腾讯云 TKE 的 etcd 备份策略` | 5s |
| 2 | Agent 输出对比表格 | 30s |
| 3 | 展示速查卡 PDF 侧边栏 | 15s |
| 4 | 展示术语词典关联词条 | 10s |
| 5 | 全屏展示速查卡全景 | 30s |

### 旁白

> "多云环境下, 同一个问题在不同平台的处理方式完全不同。kudig-database 覆盖 97 个行业场景, 218 个 CNCF 项目, 13 张速查卡, 让你在任何云上都能快速找到答案。"

### 预期画面

- 对比表格: 3 列 (AWS EKS / 阿里云 ACK / 腾讯云 TKE), 行包括备份方式/频率/存储/恢复时间
- 速查卡: 可视化对比图, 色彩编码
- 术语词典弹窗: etcd snapshot 相关术语解释

### 剪辑要点

- 表格从左到右依次显现
- 速查卡用放大镜效果聚焦
- 结尾加产品 logo + 官网地址
- 底部字幕: "多云中立 — 覆盖主流云平台的差异化知识"

## 后期剪辑指引

### 字幕

- 全程硬字幕, 字体: 思源黑体 Medium, 24px
- 关键术语用黄色 (#FFD700) 标注
- 旁白字幕白色, 底部居中
- 场景标题字幕在左上角, 带半透明黑底

### 转场

- 场景间切换: 淡入淡出 (0.5s)
- 步骤间切换: 向左滑动 (0.3s)
- 重要信息出现: 缩放弹出 (0.2s)

### BGM

- 主旋律: 轻快科技风 (推荐: Epidemic Sound "Digital Frontier" 类型)
- 音量: 旁白时降至 15%, 无旁白时 40%
- 场景 4 结尾: 音乐渐强, 配合 logo 出现

### 其他

- 片头: 3s 黑底 + kudig-database logo + 产品 slogan
- 片尾: 5s logo + 官网 + GitHub 地址 + "Star us on GitHub" CTA
- 总时长目标: 8-10 分钟
- 输出格式: MP4 (H.264, 1080p, 30fps)
