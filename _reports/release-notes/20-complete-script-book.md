[举手统计]

[停顿]

下面, 有请 [主讲人姓名] 为我们揭晓今天的主角。

[掌声, 主讲人上台]
```

## 二、演示环节过渡语

> 适用于: 每个演示场景之间的衔接

### 深度研究 → 问题排查

```
[停顿]

刚才我们看到了 Agent 的深度研究能力。
但运维工程师最常遇到的不是研究, 而是问题。

[情绪: 紧迫感]

凌晨三点, 告警响了, 你被叫醒。
Pod 一直在重启, 业务在抖动。
这时候你需要的不是一篇长文, 而是快速定位根因。

让我们看看 Agent 怎么处理。
```

### 问题排查 → 架构设计

```
[停顿]

问题排查是被动响应。
但运维工程师不只是救火, 还要建设。

[情绪: 转为轻松]

比如, 老板让你设计一套新系统的 K8s 架构。
这种任务通常需要一个架构师花一周时间。

让我们看看 Agent 能不能帮你加速。
```

### 架构设计 → 命令解读

```
[停顿]

架构设计是大任务。
但有时候, 你需要的只是一个快速解答。

[情绪: 轻松]

比如, 你看到一个报错代码, 不确定什么意思。
这种小事不需要翻文档, 直接问 Agent。
```

### 命令解读 → 数据总结

```
[停顿]

四个场景演示完了。

[情绪: 总结]

深度研究、问题排查、架构设计、命令解读。
从大任务到小问题, 从系统性知识到即时解答。

[手势: 展示屏幕]

让我们用一组数据来回顾。
```

## 三、演示失败应急预案台词

> 适用于: 现场演示出问题时的过渡

### 场景 A: Agent 响应超时 (> 10 秒)

```
[情绪: 镇定, 微笑]

看来网络有点小波动。

[停顿]

没关系, 我提前录了一段演示视频, 让我们先看录屏。

[手势: 切换到录屏]

[播放录屏]

[录屏结束后]

好的, 这就是 Agent 的实际输出。我们继续。
```

### 场景 B: Agent 输出不理想

```
[情绪: 诚实]

嗯, 这次 Agent 的输出不太理想。

[停顿]

这其实也说明了一个现实: AI 不是万能的, 它需要好的知识和好的提示词。

[情绪: 转为自信]

但在大多数场景下, kudig-database 的知识质量可以让 Agent 给出专业级的输出。

[手势: 切换到预录视频]

让我们看一段我提前准备的完整演示。
```

### 场景 C: 环境完全不可用

```
[情绪: 镇定]

看来演示环境今天有点调皮。

[轻笑]

没关系, 我为这种情况准备了完整的录屏演示。

[手势: 切换到录屏]

其实, 这也从侧面说明了一件事:
生产环境永远会有意外, 这就是为什么我们需要好的工具和好的预案。

[播放录屏]

## 四、观众 Q&A 预案

> 适用于: 演讲结束后的观众提问环节

### Q1: "这个知识库怎么接入我们现有的 Agent?"

```
好问题。我们提供了四种接入方式:

第一种, RAG Profile。我们准备了四套预配置文件,
SRE Agent、学习助手、全量语料、NotebookLM, 直接导入即可。

第二种, NotebookLM。把 Markdown 文件拖进去就行。

第三种, LangChain 或 LlamaIndex。
我们有详细的分块策略指南, 按 H2 标题分块, chunk_size 2000。

第四种, 自定义。98% 的文档有标准 front matter,
你可以按 category、tags、difficulty 过滤, 只导入你需要的部分。

5 分钟快速上手指南已经写好了, 会后可以扫码获取。
```

### Q2: "知识库会持续更新吗? 怎么保证不落后?"

```
会的。我们有三个更新机制:

第一, K8s 版本跟进。每个新版本发布后两周内更新相关文档。
目前覆盖 v1.25 到 v1.33。

第二, CNCF 项目跟进。新项目毕业或孵化时补充文档。
目前覆盖 218 个项目。

第三, 社区贡献。我们计划在 2027 年开放社区贡献,
让每一个 SRE 都可以为知识库添砖加瓦。
```

### Q3: "和 ChatGPT 直接问 K8s 问题有什么区别?"

```
本质区别是: 知识的来源和结构。

ChatGPT 的知识来自互联网爬取, 版本混杂, 无法验证。
你问它 etcd 备份, 它可能给你一个 1.19 版本的命令。

kudig-database 的知识是经过人工审核的生产实战经验,
每篇文档有版本标注, 有适用场景, 有 cross-references。

更重要的是, ChatGPT 只能给你文字回答。
kudig-database 支持的 Agent 可以调用诊断脚本,
输出结构化的排查步骤, 给你可执行的命令。

这就是"泛泛而谈"和"专家级输出"的区别。
```

这不是概念介绍, 是可以直接拿去做技术评审的架构方案。

## 五、数字人视频 — 补充台词

> 数字人视频 (19) 的逐字稿已在 19-digital-human-video.md 中
> 这里补充数字人版本的语气调整和额外场景

### 数字人语气调整说明

```
相比真人演讲, 数字人视频需要注意:

1. 语速: 比真人慢 10-15%, 给观众消化时间
2. 停顿: 比真人长 0.5-1 秒, 数字人停顿太短会显得不自然
3. 情绪: 不需要太夸张, 保持平稳自信即可
4. 手势: 数字人手势幅度减半, 避免不自然
5. 眼神: 始终看向镜头, 不要左右看
```
