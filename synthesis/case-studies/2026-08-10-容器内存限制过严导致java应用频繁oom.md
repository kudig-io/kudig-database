# 容器内存限制过严导致Java应用频繁OOM

**日期**: 2026-08-10  
**关联Skill**: [[02-pod-crashloop-oomkilled]]  
**严重级别**: P1

## 场景描述
Java微服务反复OOMKilled，容器内存限制设为2Gi但JVM堆内存设为1.5G。实际运行时JVM内存使用远超限制。

## 时间线
13:00 Java服务反复重启，状态OOMKilled
13:10 检查Pod事件：OOMKilled，内存限制2Gi
13:20 检查JVM配置：-Xmx1536m（1.5G）
13:30 分析JVM内存使用：堆1.5G + 元空间256M + 线程栈 + 直接内存 = 远超2G
13:45 理解容器内存限制包含JVM全部内存，不仅是堆
14:00 调整容器内存限制至4Gi，JVM -Xmx调整为2.5G
14:15 服务稳定运行，不再OOM
14:30 制定Java容器内存配置规范

## 根因分析
容器内存限制2Gi未考虑JVM非堆内存开销（元空间、线程栈、直接内存、JVM自身开销）。实际JVM总内存需求约3G+，远超2G限制。

## 影响评估
服务不可用约1小时，影响依赖该服务的下游10个微服务。

## 教训与预防
1. Java容器内存限制 = JVM堆 + 元空间 + 线程栈 + 直接内存 + 缓冲
2. 建议-Xmx设为容器内存限制的50-60%
3. 使用容器感知的JVM参数：-XX:+UseContainerSupport
