# 生产上线前检查项

> **使用场景**：业务（或集群整体）正式承接生产流量前逐项核验。✅ 必须 / 🔶 建议。✅ 项未通过不得切流。
>
> 与 [[06-initialization-checklist]] 的区别：初始化清单面向"集群交付"，本清单面向"业务上线"，聚焦容量、可用性、可观测性与应急能力。

## 1. 容量与资源

| # | 级别 | 检查项 | 达标标准 |
|---|---|---|---|
| 1.1 | ✅ | 集群资源水位：CPU/内存 allocatable 使用率 < 60%（预留 ≥ 20% headroom 应对扩容延迟与故障转移） | Prometheus 近 7 天数据 |
| 1.2 | ✅ | 业务 requests 基于压测数据设定，已复核 P95 使用量 | 压测报告 |
| 1.3 | ✅ | Namespace 配额（ResourceQuota/LimitRange）配置，无超卖 Namespace | 配额审计 |
| 1.4 | ✅ | 节点自动扩容能力验证：HPA 触发 → CA/Karpenter 供给 → Pod Ready 端到端时延 < SLA（通常 < 5min） | 演练记录 |
| 1.5 | ✅ | IPAM 水位 < 70%，有扩容预案 | CNI 监控 |
| 1.6 | 🔶 | 大促/高峰容量预案：预估峰值 QPS → 所需副本数 → 所需节点数，已提前扩容或备好快速扩容方案 | 容量预案文档 |

## 2. 高可用验证

| # | 级别 | 检查项 | 达标标准 |
|---|---|---|---|
| 2.1 | ✅ | 核心服务副本数 ≥ 2（有状态 ≥ 3），跨节点/跨 AZ 分布 | spec + 拓扑核验 |
| 2.2 | ✅ | PDB 配置且验证有效：`kubectl drain` 测试节点驱逐不击穿服务 | drain 演练 |
| 2.3 | ✅ | 单节点故障演练：随机杀 1 个业务节点，服务 P99 无明显劣化 | 混沌演练记录 |
| 2.4 | ✅ | 单 AZ 故障演练（核心链路）：流量切换正常 | 演练记录 |
| 2.5 | ✅ | Ingress/LB 层 HA：入口 Pod 被杀/节点故障时流量无缝切换 | 演练记录 |
| 2.6 | ✅ | 优雅下线验证：发布过程中无 5xx 尖峰（preStop + terminationGrace 配置正确） | 发布演练 |
| 2.7 | 🔶 | 依赖故障演练：下游 DB/中间件不可用时业务优雅降级而非连环崩溃 | 混沌演练 |

## 3. 监控告警闭环

| # | 级别 | 检查项 | 达标标准 |
|---|---|---|---|
| 3.1 | ✅ | 控制面监控：apiserver（时延/QPS/错误率/APF 拒绝）、etcd（延迟/磁盘/leader 切换）、scheduler、kubelet | Dashboard 核验 |
| 3.2 | ✅ | 节点监控：CPU/内存/磁盘 inode/磁盘 IO/网络/conntrack | Dashboard 核验 |
| 3.3 | ✅ | 业务监控：RED（Rate/Error/Duration）或 USE 指标接入，SLI 定义明确 | SLI/SLO 文档 |
| 3.4 | ✅ | 告警规则评审：无告警风暴（单故障触发 ≤ 3 条告警）、分级合理（P1 电话/P2 IM/P3 工单） | 告警评审记录 |
| 3.5 | ✅ | 告警通道演练：P1 告警真实触发一次，确认通知到人 | 演练记录 |
| 3.6 | ✅ | 日志：采集链路完整（stdout → agent → 存储），关键业务日志保留 ≥ 30 天 | 日志平台核验 |
| 3.7 | 🔶 | 链路追踪（Tracing）接入，核心调用链可视化 | Tracing 平台核验 |
| 3.8 | ✅ | 事件（K8s Event）外送留存，不依赖 etcd 内 TTL | 事件平台核验 |

## 4. 灾备与数据安全

| # | 级别 | 检查项 | 达标标准 |
|---|---|---|---|
| 4.1 | ✅ | etcd 定时快照 + 异地副本，最近一次恢复演练 < 90 天 | 演练记录 |
| 4.2 | ✅ | PV 数据备份策略落地（快照/应用层备份/Velero），恢复演练通过 | 演练记录 |
| 4.3 | ✅ | 核心数据 RPO/RTO 指标定义并经业务确认 | SLA 文档 |
| 4.4 | ✅ | 集群配置 GitOps 化管理：集群毁坏后可通过 Git 仓库重建 | 重建演练 |
| 4.5 | 🔶 | 跨集群/跨地域容灾方案（核心业务）：切换手册 + 演练记录 | 容灾文档 |

## 5. 性能压测

| # | 级别 | 检查项 | 达标标准 |
|---|---|---|---|
| 5.1 | ✅ | 单服务压测：确认容量拐点与瓶颈（CPU/内存/下游/连接池） | 压测报告 |
| 5.2 | ✅ | 全链路压测（核心链路）：峰值 1.5–2 倍压力下 P99 达标、无错误率上升 | 压测报告 |
| 5.3 | ✅ | HPA 行为压测验证：扩容速度跟得上流量爬升曲线；缩容不抖动 | 压测观察 |
| 5.4 | ✅ | DNS 压测/观测：高峰 QPS 下 CoreDNS/NodeLocal 无超时 | 压测观察 |
| 5.5 | 🔶 | 组件级压测（超大规模）：APIServer LIST/写压测、调度吞吐验证 | 专项报告 |

## 6. 发布与变更流程

| # | 级别 | 检查项 | 达标标准 |
|---|---|---|---|
| 6.1 | ✅ | 发布策略定义：滚动参数（maxSurge/maxUnavailable）、金丝雀/蓝绿按需 | 发布模板 |
| 6.2 | ✅ | 发布流水线：构建 → 扫描 → 预发 → 生产，生产发布需审批 | CI/CD 核验 |
| 6.3 | ✅ | 回滚方案验证：最近一次发布执行过回滚演练且 < 5 分钟 | 演练记录 |
| 6.4 | ✅ | 变更窗口与冻结期制度明确（大促/护网期间冻结非必要变更） | 制度文档 |
| 6.5 | 🔶 | 配置变更（ConfigMap/Secret）与代码发布解耦，支持独立回滚 | 流程核验 |

## 7. 应急预案

| # | 级别 | 检查项 | 达标标准 |
|---|---|---|---|
| 7.1 | ✅ | 核心场景 Runbook：集群级故障、单服务故障、存储故障、网络故障、证书到期、DNS 故障 | Runbook 库 |
| 7.2 | ✅ | 值班与升级机制：oncall 排班、15 分钟响应、升级路径明确 | 值班表 |
| 7.3 | ✅ | 降级预案：核心服务降级开关、限流预案（接入层 + 服务层）演练通过 | 演练记录 |
| 7.4 | ✅ | 通讯机制：故障群、公告模板、对内对外口径流程 | 制度文档 |
| 7.5 | 🔶 | GameDay 演练：上线前至少完成 1 次综合故障演练 | 演练记录 |

## 8. 安全就绪（上线视角）

| # | 级别 | 检查项 |
|---|---|---|
| 8.1 | ✅ | 镜像无高危漏洞（扫描报告归档） |
| 8.2 | ✅ | Pod 安全基线：non-root、只读根文件系统、drop capabilities（见 [[03-workload#6. 安全基线（工作负载侧）]]） |
| 8.3 | ✅ | 敏感信息全部走 Secret/外部密钥管理，无硬编码 |
| 8.4 | ✅ | 对外暴露面盘点：Ingress/LoadBalancer/NodePort 清单，无意外暴露 |

> 护网/重保专项见 [[08-security-defense-checklist]]。

## 9. 上线决策会（Go/No-Go）检查

最后一步：召开上线评审，逐项过 ✅ 清单，输出结论：

- **Go**：全部 ✅ 通过，🔶 项有豁免说明与跟进人
- **Conditional Go**：非关键项有明确补救计划与截止日期
- **No-Go**：任何 ✅ 项未通过且无豁免
