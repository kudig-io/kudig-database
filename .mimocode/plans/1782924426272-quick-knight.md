## 三、执行策略

### 批次规划

| 批次 | 范围 | 预估文件数 | 说明 |
|------|------|-----------|------|
| **Batch 1** | domain-09, domain-11 | ~25 个 | 可靠性 + 生产运维，生产阻塞级 |
| **Batch 2** | domain-12 补充 | ~26 个 | 6 大云厂商深度指南 |
| **Batch 3** | domain-16 | ~12 个 | 数据库/中间件补齐 |
| **Batch 4** | domain-04, domain-05, domain-06 | ~18 个 | 存储/安全/可观测中等缺失 |
| **Batch 5** | domain-08, domain-13, domain-15, domain-18, domain-20 | ~25 个 | 发布/运行时/专项/清单/应用模式 |

### 文件规范

每个新增文件必须包含：
1. **Frontmatter**: title, description, summary, category, tags, tier, created, last_updated, difficulty, reading_level, audience, estimated_read_time, intent_queries, trigger_keywords, prerequisites
2. **正文结构**: H1 标题 → 概述 → 核心内容 → 生产最佳实践 → 故障排查 → 参考链接
3. **生产就绪检查清单**: 每个文件末尾附 production readiness checklist
4. **K8s 版本兼容性**: 标注适用的 K8s 版本范围

### 验证方法

每批次完成后：
1. `wiki-lint` 检查 frontmatter 完整性
2. `wiki-status` 确认文件已纳入索引
3. 抽查 3-5 个文件的 wikilink 有效性
4. 确认无重复内容（wiki-dedup）
