# 裸金属算力平台 BMCP 纳管 ACK 容器智算集群 — 常见问题与运维手册

## 1. BMCP 与 ACK 的纳管关系

### 1.1 BMCP 是什么

BMCP（Bare Metal Computing Platform，裸金属算力平台）是 Apsara Stack 面向 AI 智算场景的 IaaS 平台，提供裸金属算力的统一管理与发放：机型管理、裸机镜像、集群发放、GPU/RDMA 监控、一键诊断、文件备份等。入口为 Apsara Uni-manager 运营控制台（首次登录需改密，密码 8~20 位至少两类字符；admin 账号权限不受限，慎重使用）。

### 1.2 三类算力集群形态

| 集群形态 | 说明 | 典型用途 |
|----------|------|----------|
| **裸金属-智算算力集群** | 直接发放裸金属组成的智算集群 | 自建调度/自研平台 |
| **容器-智算算力集群（ACK）** | BMCP 侧一键创建 ACK 集群，裸金属实例作为 BMCP Worker 节点纳管进 ACK | 容器化 AI 训练/推理 |
| **裸金属-超算算力集群** | HPC 高性能计算场景（高性能计算高网/纳管型实例） | 传统 HPC |

「ACK 纳管 BMCP」即第二种形态：在 BMCP 控制台「集群与节点 > 集群管理 > 容器-智算算力集群」页签创建集群，Worker 节点可选 **ECS Worker 节点**或 **BMCP Worker 节点**（裸金属）。创建后仍可跳转 ACK 控制台、通过 kubeconfig 用 kubectl 直连。

### 1.3 四种实例规格（选型错误是常见问题根源）

| 实例规格 | 网络 | 存储 | Worker 配置方式 |
|----------|------|------|-----------------|
| **智算高网型** | 原生 RDMA 高带宽网络（可配 RDMA EVPC） | 支持高性能存储（CPFS/APFS） | 选规格 + 配数量 |
| **智算纳管型** | **利旧纳管**客户已有 IB/RoCE 网络 | 传统存储 + 可挂三方存储（iSCSI/NFS/直接挂载） | **选节点 + 配镜像** |
| **智算基础型** | 基础网络，不支持高带宽网络/高性能存储 | 本地盘为主 | 选规格 + 配数量 |
| **智算训推优化型** | CPN（Computing Platform Network） | APFS | 选规格 + 配数量 |

> 纳管型接入方式可选 **CHSW 接入 / HSW 接入**（仅纳管型实例有此参数）。监控概览中实例分类还包括高性能计算高网/纳管型（属超算形态）。

### 1.4 端到端纳管链路

```
Apsara Uni-manager 运营控制台
 └─ BMCP 运维控制台：裸机管理 BMS（装机/注册实例/节点状态）
     └─ BMCP 用户控制台：集群与节点 > 集群管理 > 容器-智算算力集群
         ├─ 容器服务 RAM 角色授权 + 云接入网关（CGW）RAM 角色授权
         ├─ 选择 VPC/VSwitch、K8s 版本、Master(ECS)、Worker(ECS/BMCP)
         └─ 创建成功 → 连接信息页签取 kubeconfig / 跳转 ACK 控制台
```

## 2. 高频常见问题速查表（现象 → 原因 → 处理）

| # | 现象 | 根因 | 处理 |
|---|------|------|------|
| 1 | 创建集群时提示组织未授权，无法继续 | 容器服务 RAM 角色或云接入网关（CGW）RAM 角色未授权 | 授权组织完成**两项**授权；授权后点刷新按钮刷新状态再继续 |
| 2 | BMCP Worker 节点列表为空/选不到节点 | 实例未在 BMCP 运维控制台注册，或裸金属节点状态异常 | 到 Uni-manager 运维控制台 - BMCP 运维平台确认实例注册与运行状态 |
| 3 | 纳管后节点起不来/组件异常 | Worker 镜像不在支持列表（架构/内核不符） | 按镜像白名单重装：x86 用 Alibaba Cloud Linux 3（5.10.x）等，详见 §3.2 |
| 4 | Master 规格下拉为空 | 可选规格数量 = 所选 vSwitch 数量 N（N ≤ Master 数量） | 多选几个 vSwitch，或改用 3 Master 降低规格需求 |
| 5 | 创建页没有目标 K8s 版本 | 版本硬约束 | 仅支持 `1.32.7-aliyun.1` / `1.30.7-aliyun.1` |
| 6 | Pod/Service CIDR 校验失败 | 与 VPC 网段或同 VPC 已有 K8s 集群网段冲突 | 重新规划网段；**创建成功后不可修改** |
| 7 | 集群内无法访问公网/拉不到公网镜像 | 未勾选「配置 SNAT」 | 为 VPC 创建 NAT 网关并配置 SNAT 规则，或重建时勾选 SNAT |
| 8 | kubectl 连不上集群 | API Server 未暴露公网（默认仅 VPC 内访问）；kubeconfig 未落对位置 | 在 VPC 内访问；连接信息页签复制配置到 `$HOME/.kube/config`；kubectl 版本用连接页提供的对应版本 |
| 9 | 纳管后节点数据盘数据丢失 | 最后一块未初始化数据盘被自动格式化挂 `/var/lib/docker`、`/var/lib/kubelet` | **纳管前备份**，见 §4 红线 R1 |
| 10 | 缩容报错/受限 | 开启高性能存储的集群缩容后节点 < 3 | CPFS 最少 3 节点、APFS 最少 1 节点，先缩存储或调整方案 |
| 11 | 误删节点/误删集群 | 无删除保护 | 开启「集群删除保护」；实例保护默认开启且不可关（兜底防其他产品释放裸机） |
| 12 | 删除后节点找不到了 | 节点进入回收站冷冻期（1~720 小时） | 回收站页签恢复；超时自动释放回资源池并重装 OS |
| 13 | 扩容/创建操作失败 | 多为授权、镜像、节点状态、库存问题 | 集群详情 → 操作记录 → 聚合日志 → 对失败任务**重试**或**诊断** |
| 14 | 巡检/压测时业务 GPU 变慢 | 一键诊断的耗时诊断项、压力测试会占用 GPU | 避开业务高峰执行巡检 |
| 15 | 性能评测任务无法创建 | 集群未安装容器运维服务 | 软件实例页签安装集群运维服务（启用后需通过安装 Addon 触发实际 ECS 资源） |
| 16 | DADI 镜像不可用 | ACK 集群未部署「DADI 镜像加速」Addon | 在集群内按需增量部署该 Addon（数据加速创建的镜像转换任务生成的 DADI 镜像才能生效） |
| 17 | 审计日志缺失 | 创建时未开启日志服务 | 日志服务开启后才有集群审计功能（自动创建 `k8s-log-{ClusterID}` Project） |
| 18 | GPU 虚拟化开启失败 | 硬件虚拟化开启时 GPU 上有任务在跑 | 确保目标 GPU 空闲后再开启；核对显卡是否在支持列表（§8） |
| 19 | 特权容器申请 KGPU 资源失败 | KGPU 使用限制 | 特权容器（privileged）无法使用 KGPU |
| 20 | 事件报警回调收不到 | 回调地址配了 IP | 报警回调必须使用域名（http:// 或 https:// 开头），不能使用 IP |

## 3. 创建/纳管阶段专项

### 3.1 前置条件核对清单

- 🟢 已具备可创建容器-智算算力集群的 **VPC 和 vSwitch**；
- 🟢 Master 节点具备可选 **ECS 实例规格**（Master 数量支持 3 / 5）；
- 🟢 待纳管的 **BMCP Worker 节点镜像符合白名单**（§3.2）；
- 🟢 BMCP 实例已在 **BMCP 运维控制台注册**；
- 🟢 裸金属节点**运行状态正常**（状态查询途径：Uni-manager 运维控制台 - BMCP 运维平台）；
- 🟢 组织已完成**容器服务 RAM 角色**与**云接入网关 RAM 角色**两项授权。

### 3.2 BMCP Worker 镜像白名单

| 架构 | 镜像 | 内核 | 支持范围 |
|------|------|------|----------|
| AMD64/x86_64 | Alibaba Cloud Linux 3 | 5.10.X | 高网型、纳管型、基础型均支持 |
| AMD64/x86_64 | Alibaba Cloud Linux 3 Pro | 5.10.X | 纳管型 + 部分基础型机型（昆仑芯 P800、ZW810E） |
| AMD64/x86_64 | Ubuntu 22.04 | 5.15.X | **仅纳管型** |
| ARM64 | Alibaba Cloud Linux 3 ARM 版 | 5.10.X | 高网型、纳管型、基础型均支持 |

> 智算基础型若选择「重新安装镜像」，仅 `PG8AP6M7S4G5VB2X7.32`、`PG8AP6M7S4G5VB2X7.03CH`、`QPG88P4M10G26B2.32` 三个机型支持指定公共镜像安装（扩容时同理）。

### 3.3 关键配置约束

| 配置项 | 约束 |
|--------|------|
| 集群名称 | 1~63 字符，字母/数字/`.`/`_`/`-`/`:`，不能以特殊字符或数字开头 |
| 登录密码 | 8~30 位，至少含大写/小写/数字/特殊字符中的三类 |
| Kubernetes 版本 | 仅 `1.32.7-aliyun.1`、`1.30.7-aliyun.1` |
| Master 节点 | 数量 3 或 5；规格候选数 = vSwitch 数量（上限 = Master 数量）；系统盘支持超高速盘/本地 SSD/高性能盘/标准性能盘 |
| Pod CIDR | 10.0.0.0/8、172.16~31.0.0/12~16、192.168.0.0/16 及其子网；不得与 VPC 网段及同 VPC 已有 K8s 集群网段重复；**创建后不可改** |
| Service CIDR | 上述网段的 /16~/24；同上约束，创建后不可改 |
| ECS Worker | 最多 10 个实例规格（按顺序重试直到创建成功）；数据盘支持高效云盘/SSD 云盘/高性能云盘/普通性能云盘；创建过程自动格式化最后一块数据盘挂 `/var/lib/docker` |
| BMCP Worker | 配置节点池名称、**裸机专用 VSwitch**、数据盘挂载；高网/基础/训推型选规格，纳管型选节点 |
| 计费配置 | 仅当管理员在运营中心配置了计费规则才显示 |

### 3.4 网络与可达性

- **配置 SNAT**：不勾选则需自建 NAT 网关 + SNAT 规则，否则节点/应用无公网出口。
- **API Server 暴露**：选择不开放 EIP 时无法从外网访问集群 API Server；连接信息页签提供的公网/内网 kubeconfig 均注明集群未暴露公网时仅支持 VPC 内访问。
- **日志服务**：不开启则无集群审计功能。

### 3.5 连接与凭据

```bash
# 🟢 连接集群（先在 连接信息 页签复制 kubeconfig 到 $HOME/.kube/config）
kubectl get nodes
kubectl get po test-pod   # KGPU 验证 Pod，详见 §8.2
```

- kubectl 客户端从「连接信息 → Kubernetes 版本」页下载匹配版本。
- 支持**公网访问 / 内网访问 / SSH** 三种连接信息。
- 多租场景支持**吊销集群 KubeConfig**（人员离职、凭证疑似泄露时吊销重发）。

## 4. 数据安全红线（🔴 必须逐条核对）

| # | 红线 | 说明 |
|---|------|------|
| R1 | **纳管会格式化数据盘** | BMCP 节点已挂数据盘且**最后一块未初始化**时，纳管自动格式化为 ext4，挂载 `/var/lib/docker` 和 `/var/lib/kubelet`，盘上原有数据**全部丢失**。未挂数据盘则不会新挂。纳管/扩容前必须确认并备份 |
| R2 | **缩容/删除的「清理数据盘」选项** | 勾选后缩容时清理数据盘数据；回收站「彻底删除」同样有该选项 |
| R3 | **缩容释放 = 删 OS + 清磁盘** | 智算算力集群裸机被缩容释放后，系统**自动删除裸机的 OS 并清理磁盘数据**，重新释放回裸机资源池 |
| R4 | **冷冻期后重装** | 回收站节点超过冷冻时长（1~720 小时）自动释放回资源池并**重装**，不可再恢复 |
| R5 | **卸载高性能存储中断业务** | 卸载会终止集群内所有使用该文件系统的进程，未保存数据丢失/服务中断；**停用**高性能存储会默认卸载当前集群挂载的所有高性能存储文件系统 |
| R6 | **实例保护不可关** | 实例保护默认打开且无法变更，防止其他产品通过控制台/API 直接删除释放集群内裸机节点（这是保护不是故障） |
| R7 | **EVPC 删除影响网络** | 删除 EVPC 会对通用智算集群型实例的网络产生影响，谨慎操作 |
| R8 | **删除集群需二次确认** | 输入「确认删除」方可执行；仅稳定状态（运行中、创建失败、扩容失败、缩容失败）可删除 |

## 5. 扩缩容专项

### 5.1 扩容（🟡）

- 前提：集群已创建、BMCP 实例已在运维控制台注册、裸金属节点状态正常。
- ECS Worker：选 VSwitch、规格、数量、系统盘/数据盘、操作系统。
- BMCP Worker：配置节点池、裸机专用 VSwitch、数据盘挂载，勾选待纳管节点。
- **纳管型注意两点**：① 是「选节点 + 配镜像」而非选规格；② 版本升级前的存量纳管型实例，扩容时需**额外配置可用区**。
- 数据盘挂载红线 R1 在扩容时同样适用。

### 5.2 缩容（🔴）

- 前提：集群内存在可缩容裸机。
- **开启高性能存储的集群，缩容后节点数不得少于 3**（CPFS 最小 3 节点、APFS 最小 1 节点）。
- 可选 BMCP Worker 节点（必选）与 ECS Worker 节点；可选清理数据盘（红线 R2）。
- 冷冻时长 1~720 小时：期内可从回收站恢复至原集群；超时自动释放回资源池（红线 R3/R4）。
- 走服务管理订单流程：已创建「裸金属算力平台 BMCP / 容器-智算算力集群」服务则「确认订单」，否则「提交」。

### 5.3 删除集群（🔴）

- 仅稳定状态可删除（运行中、创建失败、扩容失败、缩容失败）。
- 删除后裸机节点全部进回收站，冷冻期后释放进资源池并重装。
- 建议提前开启「集群删除保护」。

### 5.4 回收站

- 支持**恢复**、**彻底删除**（可选清理数据盘）、批量恢复、批量彻底删除。
- 典型误操作恢复路径：缩容/删除后节点「消失」→ 回收站页签 → 筛选 → 恢复。

## 6. 网络专项

### 6.1 VPC / EVPC / RDMA

| 对象 | 作用 | 常见问题 |
|------|------|----------|
| VPC + vSwitch | 集群基础网络与 Master/Worker 互通 | vSwitch 数量决定 Master 规格候选；裸机专用 VSwitch 独立配置 |
| EVPC | 管理智算节点 **RDMA 网络**：RDMA 网段/子网管理、不同智算集群间 RDMA 网络隔离 | **只有通用智算集群型实例支持配置 EVPC**；RDMA 网络 EVPC 参数仅高网型/训推优化型可选 |
| ECR | 裸金属网络绑定/解绑 ECR（高速通道网关） | 绑定/解绑在「网络与安全 > 裸金属网络」 |
| 通信库 | RDMA 通信库的查询/下载/复制文件地址 | 「网络与安全 > EVPC管理 > 通信库管理」 |

### 6.2 安全组与密钥对

- 安全组为虚拟防火墙，控制 BMCP 实例入/出流量，可划分安全域；支持安全组、安全组规则、安全组内实例管理。
- 密钥对提供登录认证方式（公钥/私钥），用于权限管理。

## 7. 存储专项

### 7.1 高性能存储（CPFS/APFS）

- 仅**智算高网型**和**智算训推优化型**集群支持启用。
- 节点数下限：**CPFS ≥ 3、APFS ≥ 1**，且需已部署对应高性能存储（并行文件系统客户端集群由 BMCP 部署）。
- 启用 → 挂载（选存储 + 填挂载路径）→ 卸载 → 停用；卸载/停用的数据中断风险见红线 R5。
- 缩容联动：开启高性能存储的集群缩容后节点 ≥ 3（§5.2）。

### 7.2 三方存储（纳管型专属）

- 集群级：高级配置勾选挂载三方存储，类型支持 **iSCSI / NFS / 直接挂载**，各自参数不同（如 iSCSI 需服务端 IP/域名 + IQN）。
- 节点级：「节点管理」支持为智算纳管算力集群节点挂载基于 NFS 和 iSCSI 协议的远程文件系统，支持配置多块存储批量挂载。

### 7.3 文件备份（快照）

- 为裸金属节点创建快照，备份/恢复整个文件系统目录，支持周期或手动。
- 限制：仅支持智算高网型、智算基础型实例（容器-智算集群）；**纳管型不在支持范围**；仅支持数据盘或系统盘下的目录。
- 备份仓库依赖 OSS bucket：需**读写权限为公共读写**、授权所有用户完全控制整个 Bucket、访问方式 HTTP（专有云内网 OSS）。

## 8. GPU 专项

### 8.1 GPU 虚拟化支持矩阵

| 显卡 | 支持的虚拟化方式 |
|------|------------------|
| APG | 仅**用户态虚拟化** |
| 海光 K100-AI / BW1000 | 仅**硬件虚拟化** |
| 部分 A 系列 NVIDIA | 硬件虚拟化 + 内核虚拟化 |

- 🔴 **开启硬件虚拟化时，GPU 上不能有正在执行的任务，否则开启失败**。
- 开启/关闭入口：节点详情页 GPU 虚拟化区域，或在集群与节点 > 集群管理中操作。

### 8.2 KGPU（GPU 共享/虚拟化资源调度）

- 前提：集群存在 ECS 实例且已启用集群运维服务；已安装 **KGPU 套件 + BMCP GPU Toolkit**；已启用用户态虚拟化。
- 资源单位：`kgpu.com/gpu-count`、`kgpu.com/gpu-mem`、`kgpu.com/gpu-core.percentage`；`gpu-count` 为 0 或 1 调度到一张物理卡（0 必须搭配其他资源申请），>1 调度到多张物理卡。
- 隔离策略由 `kube-system/kgpu-dp` ConfigMap 的 `shareModel` 控制：`0` 不启用 / `1` 显存隔离 / `3` 显存 + 算力双重隔离（默认双重）；修改后需重启 kgpu DaemonSet 生效。
- 🔴 **特权容器（privileged）无法使用 KGPU**。

### 8.3 GPU 事件监控

事件监控覆盖算力集群 **GPU PCIE/驱动掉卡、计算引擎异常、PCIE 链路带宽下降、NVLink 故障**等指标；支持严重/警告/提示三级报警规则、多联系人、报警历史查询。报警回调必须为域名。

## 9. 运维与诊断

### 9.1 操作记录与失败重试

- 集群详情 → 操作记录：**聚合日志**（创建/删除/扩容/缩容/启用/停用高性能存储客户端等，可下钻任务明细）与**操作日志**（操作人/状态/源 IP）。
- 聚合日志中失败任务可**重试**；可对失败操作发起**诊断**。
- 🟢 操作日志默认仅保存 **7 天**；需管理员在「配置 > 日志转存设置」调长，且**延长后不补历史数据**。

### 9.2 一键诊断（巡检）

| 巡检对象 | 巡检项 | 目的 |
|----------|--------|------|
| 裸金属集群算力巡检 | 整机巡检、GPU 巡检 | 硬件故障、性能瓶颈，展示实时健康状态 |
| 容器集群算力巡检 | 整机巡检、GPU 巡检、**k8s 底座巡检** | IaaS/PaaS 层故障、容器运行异常 |

- 🔴 含耗时诊断项或压力测试的巡检**会占用 GPU 资源**，须避开业务高峰。
- 巡检入口：运维管理 > 一键诊断 > 一键巡检（选集群类型/集群/巡检项）。

### 9.3 监控体系

- **集群监控**：基础监控（CPU/内存/磁盘/负载/TCP 连接数/网络带宽）、GPU 监控（温度/功率/利用率/编解码器/帧缓存）、RDMA 监控（发送/接收吞吐、缓冲区溢出数、报文乱序数）。
- **节点监控**：节点详情页查看。
- **概览大盘**：实例概览、GPU/CPU 算力统计、组织使用率排行（近 7/15/30 天，按芯片与实例分类）、配额统计、资源告警、P1/P2/P3 告警统计与趋势；资源告警可跳转云监控报警历史（云监控指标空间 `acs_bmcp`）。

### 9.4 Addon 与软件实例

- 容器集群支持**按需增量部署** Addon：数据缓存加速、镜像加速（DADI）、弹性容错等。
- **集群运维服务**：软件实例页签启用；⚠️ 打开服务**不会立即安装**依赖的 ECS 实例资源，需通过**安装 Addon 触发**；安装时配置 VSwitch、ECS 规格/数量、系统盘、操作系统、SLB 规格与网络。
- **软件实例**：安装/查看/删除；AI 开发控制台从软件实例访问。
- **性能评测**：创建训练/推理评测任务前，集群必须已安装**容器运维服务**（未安装时界面提供「去安装」入口）。

### 9.5 镜像与数据加速

- **镜像中心**：训练/推理/基础镜像（集成 OS、训练框架、CUDA/ROCm、高网驱动、NCCL 优化等），支持**镜像验签**，可跳转 ACR 控制台。
- **DADI 镜像加速**：按需加载，仅下载解压容器启动必需部分；数据加速页创建镜像转换任务生成的 DADI 镜像在镜像中心透出，**使用前提是 ACK 集群已部署 DADI 镜像加速 Addon**（高频问题 #16）。
- **缓存加速**：面向训练/推理的数据缓存加速；支持配置 **Dragonfly** 镜像仓库加速。
- **机型与镜像**：节点机型需先添加才可在创建集群/实例时选到；裸机镜像支持自定义镜像上传/导出/删除与公共镜像管理。

## 10. 纳管前检查清单（Checklist）

- [ ] 组织已完成容器服务 RAM 角色授权 + 云接入网关 RAM 角色授权
- [ ] VPC/vSwitch 已创建，vSwitch 数量满足 Master 规格候选需求
- [ ] Master 可用 ECS 实例规格确认（3 或 5 节点）
- [ ] BMCP 实例已在运维控制台注册，节点状态正常（BMCP 运维平台确认）
- [ ] Worker 镜像在白名单内（架构/发行版/内核三查）
- [ ] **待纳管节点数据盘已备份**（红线 R1）
- [ ] Pod/Service CIDR 规划无冲突（创建后不可改）
- [ ] SNAT / API Server 暴露方式 / 日志服务（审计）按需勾选
- [ ] 集群删除保护开启
- [ ] 需要 KGPU/GPU 虚拟化时：显卡在支持矩阵内、运维服务与套件安装顺序排好
- [ ] 缩容预案：高性能存储节点下限（≥3）、冷冻期、数据盘清理选项已评审

## 11. 面试快问快答

**Q1：专有云里 ACK 怎么纳管裸金属算力？**

- **一句话**：在 BMCP（裸金属算力平台）控制台创建容器-智算算力集群，裸金属实例注册后作为 BMCP Worker 节点纳管进 ACK。
- **30 秒答**：BMCP 是 Apsara Stack 面向 AI 智算的裸金属 IaaS，先在运维控制台注册裸机实例并保证状态正常，然后在 BMCP 用户控制台选实例规格（高网/纳管/基础/训推优化）、配 VPC/vSwitch 与 K8s 版本创建 ACK 集群；Worker 可选 ECS 或 BMCP 裸金属，创建后拿 kubeconfig 直连或跳转 ACK 控制台。
- **追问**：纳管型实例和高网型差别？——纳管型是利旧纳管客户已有 IB/RoCE 网络和传统存储，创建时按「选节点 + 配镜像」方式圈定裸机，可挂 iSCSI/NFS 三方存储；高网型是原生 RDMA + CPFS/APFS 高性能存储，按规格发放。
- **红线**：别把「ACK 纳管 BMCP」与「ACK One 注册集群（纳管外部 K8s 集群）」混为一谈——前者是裸金属算力纳管进新建 ACK，后者是存量集群接入舰队。

**Q2：纳管最常见的创建失败原因？**

- **一句话**：RAM 双授权、镜像白名单、实例未注册/状态异常、规格与 vSwitch 联动、网段冲突五类。
- **30 秒答**：①组织未做容器服务 + 云接入网关两项 RAM 授权；②Worker 镜像不在白名单（AL3 5.10/AL3 Pro/Ubuntu22.04 仅纳管型/AL3 ARM）；③BMCP 实例未注册或节点状态不正常；④Master 可选规格数 = vSwitch 数量，选少了下拉为空；⑤Pod/Service CIDR 与 VPC 或同 VPC 已有集群冲突，且创建后不可改。失败后走操作记录 → 聚合日志 → 重试/诊断。
- **追问**：K8s 版本能不能随便选？——不能，该版本 BMCP 仅放行 1.32.7-aliyun.1 和 1.30.7-aliyun.1。
- **红线**：CIDR 创建后不可修改，规划错了只能重建。

**Q3：纳管过程会动节点上的数据吗？**

- **一句话**：会——最后一块未初始化数据盘被自动格式化为 ext4 挂 /var/lib/docker 与 /var/lib/kubelet，原有数据全丢。
- **30 秒答**：纳管与扩容都会触发；没挂数据盘则不会新挂。此外缩容释放会自动删 OS 并清磁盘，回收站超过冷冻期（1~720 小时）自动释放回资源池并重装；缩容/彻底删除还有「清理数据盘」勾选项。所以数据盘备份是纳管前硬性检查项。
- **追问**：怎么防误删整个集群？——集群删除保护开关 + 删除时输入「确认删除」二次确认；实例保护默认开启且不可关，兜底防其他产品释放裸机。
- **红线**：把「实例保护默认开启」当成故障去关是错的，它关不掉。

**Q4：纳管型集群存储有什么限制？**

- **一句话**：高性能存储（CPFS/APFS）仅高网型和训推优化型支持，且开启后缩容节点数不得少于 3。
- **30 秒答**：CPFS 最小 3 节点、APFS 最小 1 节点，且需已部署对应存储；纳管型的价值在三方存储——集群级支持 iSCSI/NFS/直接挂载，节点级支持 NFS/iSCSI 远程文件系统批量挂载。文件备份快照只覆盖高网型/基础型，纳管型不在范围。
- **追问**：停用高性能存储要注意什么？——会默认卸载该集群挂载的所有高性能文件系统，卸载动作会终止使用进程，先卸载业务文件系统再停用。
- **红线**：给纳管型集群开 CPFS 是配置错误——它不在支持列表。

**Q5：GPU 智算场景运维有哪些专属能力与坑？**

- **一句话**：GPU 虚拟化 + KGPU 共享调度 + GPU/RDMA/事件监控 + 一键巡检；坑在虚拟化开启条件与巡检占卡。
- **30 秒答**：GPU 虚拟化按卡型分路——APG 仅用户态、海光 K100-AI/BW1000 仅硬件虚拟化、部分 A 系 NVIDIA 两者皆可；开硬件虚拟化必须 GPU 空闲否则失败。KGPU 提供 kgpu.com 三类资源（count/mem/core.percentage），shareModel 控制隔离（0 关闭/1 显存/3 显存+算力），特权容器不可用。事件监控覆盖 GPU 掉卡、NVLink 故障、PCIE 带宽下降；一键巡检的压测项会占 GPU，要避开业务。
- **追问**：RDMA 网络怎么隔离？——EVPC 管理智算节点 RDMA 网段/子网并隔离不同智算集群，仅通用智算集群型实例支持。
- **红线**：巡检压测跑在生产 GPU 集群上不做窗口评审，属于变更事故。

**Q6：BMCP 侧运维排查的标准动作？**

- **一句话**：操作记录聚合日志定位失败任务 → 重试/诊断 → 一键巡检分层（整机/GPU/k8s 底座）→ 事件监控与云监控（acs_bmcp）看硬件与告警。
- **30 秒答**：先看集群详情操作记录，聚合日志下钻到子任务，失败可直接重试或发起诊断；容器集群巡检覆盖 IaaS/PaaS 两层；事件监控配严重/警告/提示三级报警（回调必须域名）；注意操作日志默认只留 7 天，需要审计留存要提前让管理员改日志转存设置。
- **追问**：节点级硬件问题怎么进一步定位？——结合节点 BMC/IPMI SEL 日志与硬件排障流程（见 [[skills/03-节点/node/01-node-notready-diagnosis.md|节点 NotReady 诊断]]、[[wiki/17-系统基础/02-硬件/10-hardware-troubleshooting-methodology.md|硬件排障方法论]]）。
- **红线**：日志转存调长不补历史数据，出事后才改已经晚了。
