# 阿里云专有云远程顾问指南

本文档面向部署在客户环境之外的智能体/远程顾问，系统阐述在无法直接访问客户专有云环境时的远程诊断方法论、工具链使用和沟通规范。

---

## 1. 远程诊断方法论

### 1.1 远程诊断约束

```
┌──────────────────────────────────────────────────────────┐
│                    远程顾问（无直接访问）                    │
│  约束：                                                  │
│  • 无法SSH到客户节点                                      │
│  • 无法直接执行kubectl                                    │
│  • 无法访问客户内部系统                                   │
│  • 无法查看客户监控大屏                                   │
└─────────────────────────┬────────────────────────────────┘
                          │ 工单/企微/钉钉/邮件
                          ↓
┌──────────────────────────────────────────────────────────┐
│                    客户运维人员                            │
│  权限：                                                  │
│  • 堡垒机SSH访问                                         │
│  • kubectl集群管理权限                                    │
│  • ASCM/ASO控制台访问                                     │
│  • 内部工单系统权限                                       │
└──────────────────────────────────────────────────────────┘
```

### 1.2 远程诊断流程

| 阶段 | 顾问行动 | 客户行动 | 交付物 |
|------|----------|----------|--------|
| **信息收集** | 发送诊断问卷 | 填写环境信息 | 环境拓扑图 |
| **症状确认** | 追问异常表现 | 提供截图/日志 | 问题描述文档 |
| **诊断指令** | 发送检查命令 | 在堡垒机执行 | 命令输出 |
| **根因分析** | 分析输出结果 | 补充信息 | 根因分析报告 |
| **方案制定** | 编写修复步骤 | 确认可行性 | 修复方案 |
| **实施指导** | 实时指导操作 | 执行修复 | 操作记录 |
| **验证确认** | 发送验证命令 | 执行验证 | 验证结果 |
| **知识归档** | 更新知识库 | 确认无误 | 案例文档 |

## 2. OpenAPI/SDK远程诊断

### 2.1 专有云OpenAPI接入

```python
# 专有云OpenAPI诊断脚本
from alibabacloud_cs20151215 import Client as CSClient

def diagnose_cluster(client, cluster_id):
    results = {}
    try:
        resp = client.describe_cluster_detail(cluster_id)
        results['cluster'] = {
            'state': resp.body.state,
            'version': resp.body.kubernetes_version
        }
    except Exception as e:
        results['error'] = str(e)
    return results
```

## 3. Console操作替代kubectl

### 3.1 ASCM控制台操作映射

当客户不熟悉 kubectl 时，可通过 ASCM 控制台完成大部分操作：

| kubectl操作 | ASCM控制台路径 | 远程指导话术 |
|-------------|---------------|-------------|
| `kubectl get nodes` | 容器服务 → 集群 → 节点 | "请进入容器服务控制台，点击集群名称，切换到节点标签页" |
| `kubectl get pods` | 容器服务 → 集群 → 工作负载 | "请点击左侧工作负载菜单，查看Pod列表" |
| `kubectl logs` | 容器服务 → 集群 → Pod详情 → 日志 | "点击目标Pod名称，切换到日志标签页，选择容器" |
| `kubectl describe` | 容器服务 → 集群 → 资源详情 | "点击资源名称，查看右侧详情面板" |
| `kubectl exec` | 容器服务 → 集群 → Pod详情 → 终端 | "点击Pod名称，打开Web终端" |
| `kubectl apply` | 容器服务 → 集群 → YAML创建 | "点击YAML创建按钮，粘贴以下配置" |
| `kubectl scale` | 容器服务 → 集群 → [[entities/deployment.md|Deployment]] → 伸缩 | "找到对应Deployment，修改副本数" |
| `kubectl top` | 容器服务 → 监控 → 集群监控 | "切换到监控页面，查看资源使用" |

### 3.2 Web终端使用

ASCM 控制台提供 Web 终端功能，可用于无法使用 kubectl 的客户：

```
ASCM控制台路径：
容器服务 → 选择集群 → 节点管理 → 点击节点 → 远程连接 → WebSSH

或使用：
容器服务 → 选择集群 → 工作负载 → 点击Pod → 终端
```

**远程指导话术**：

```markdown
【Web终端操作指引】

请按以下步骤操作：

1. 登录 ASCM 控制台：___（客户提供地址）
2. 进入「容器服务」模块
3. 选择目标集群：___
4. 进入「节点管理」
5. 找到目标节点，点击「远程连接」
6. 在弹出的终端中执行以下命令：

```
docker ps | grep <container-name>
docker logs <container-id>
```

或进入容器：
```
docker exec -it <container-id> /bin/sh
```
```

### 3.3 YAML编辑器使用

```markdown
【通过ASCM YAML编辑器修改配置】

请按以下步骤操作：

1. 进入 ASCM 控制台 → 容器服务 → 选择集群
2. 进入「配置与存储」→「配置项」或「保密字典」
3. 点击「创建」或找到目标资源点击「编辑"
4. 在YAML编辑器中粘贴以下配置：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: [[entities/coredns.md|coredns]]
  namespace: kube-system
data:
  Corefile: |
    .:53 {
        errors
        health
        kubernetes cluster.local in-addr.arpa ip6.arpa {
           pods insecure
           fallthrough in-addr.arpa ip6.arpa
        }
        forward . 10.0.1.10 10.0.1.11
        cache 30
    }
```

5. 点击「确定」保存
6. 重启CoreDNS Pod使其生效：
   进入「工作负载」→「DaemonSets」→ 找到 coredns → 点击「重新部署」
```

### 4.2 内部工单系统对接

```python
# 内部工单系统API对接示例
import requests
import json

def create_internal_ticket(
    ticket_system_url,
    api_key,
    cluster_id,
    issue_type,
    description,
    diagnosis_data,
    priority="P2",
    contact_info=None
):
    """创建内部技术支持工单"""
    
    payload = {
        "title": f"[ACK专有云] {issue_type} - {cluster_id}",
        "category": "cloud-infrastructure",
        "sub_category": "ack-private-cloud",
        "priority": priority,
        "description": description,
        "cluster_id": cluster_id,
        "cloud_provider": "alibaba-cloud",
        "deployment_type": "apsara-stack",
        "diagnosis_data": diagnosis_data,
        "contact": contact_info or {
            "name": "客户运维",
            "channel": "企业微信工单群"
        },
        "attachments": []
    }
    
    headers = {
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json"
    }
    
    resp = requests.post(
        f"{ticket_system_url}/api/v1/tickets",
        headers=headers,
        json=payload,
        timeout=30
    )
    
    return resp.json()

def update_ticket_status(ticket_id, status, comment, api_key, ticket_system_url):
    """更新工单状态"""
    payload = {
        "status": status,  # open, in_progress, resolved, closed
        "comment": comment,
        "updated_by": "remote-advisor-agent"
    }
    
    headers = {
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json"
    }
    
    resp = requests.patch(
        f"{ticket_system_url}/api/v1/tickets/{ticket_id}",
        headers=headers,
        json=payload,
        timeout=30
    )
    
    return resp.json()
```

## 5. 远程诊断工具箱

### 5.1 一键诊断命令包

```bash
#!/bin/bash
# ACK 专有云一键诊断（客户执行，输出压缩包给顾问）

DIAG_DIR="/tmp/ack-diag-$(date +%Y%m%d-%H%M%S)"
mkdir -p $DIAG_DIR/{cluster,nodes,network,storage,logs}

# 1. 集群信息
kubectl cluster-info > $DIAG_DIR/cluster/cluster-info.txt 2>&1
kubectl version --short > $DIAG_DIR/cluster/version.txt 2>&1
kubectl get nodes -o wide > $DIAG_DIR/cluster/nodes.txt 2>&1
kubectl get pods -A -o wide > $DIAG_DIR/cluster/all-pods.txt 2>&1
kubectl get events --sort-by='.lastTimestamp' > $DIAG_DIR/cluster/events.txt 2>&1

# 2. 节点信息
kubectl top nodes > $DIAG_DIR/nodes/top-nodes.txt 2>&1
for node in $(kubectl get nodes -o jsonpath='{.items[*].metadata.name}'); do
    kubectl describe node $node > $DIAG_DIR/nodes/describe-$node.txt 2>&1
done

# 3. 网络信息
kubectl get svc -A > $DIAG_DIR/network/services.txt 2>&1
kubectl get ingress -A > $DIAG_DIR/network/ingress.txt 2>&1
kubectl get networkpolicies -A > $DIAG_DIR/network/networkpolicies.txt 2>&1
kubectl get pod -n kube-system -l app=terway-eniip -o wide > $DIAG_DIR/network/terway-pods.txt 2>&1
for pod in $(kubectl get pods -n kube-system -l app=terway-eniip -o name); do
    kubectl logs -n kube-system $pod --tail=200 > $DIAG_DIR/network/logs-$(basename $pod).txt 2>&1
done

# 4. 存储信息
kubectl get pv > $DIAG_DIR/storage/pvs.txt 2>&1
kubectl get pvc -A > $DIAG_DIR/storage/pvcs.txt 2>&1
kubectl get sc > $DIAG_DIR/storage/storageclasses.txt 2>&1
kubectl get pods -n kube-system | grep csi > $DIAG_DIR/storage/csi-pods.txt 2>&1

# 5. 系统组件日志
kubectl logs -n kube-system -l k8s-app=kube-dns --tail=500 > $DIAG_DIR/logs/coredns.txt 2>&1
kubectl logs -n kube-system -l k8s-app=kube-proxy --tail=500 > $DIAG_DIR/logs/kube-proxy.txt 2>&1
kubectl logs -n kube-system -l component=kube-apiserver --tail=500 > $DIAG_DIR/logs/apiserver.txt 2>&1 2>/dev/null

# 打包
tar czf $DIAG_DIR.tar.gz -C $(dirname $DIAG_DIR) $(basename $DIAG_DIR)
echo "诊断包已生成: $DIAG_DIR.tar.gz"
echo "请将该文件发送给远程顾问"
```

### 5.2 安全注意事项

| 敏感信息 | 处理方式 | 说明 |
|----------|----------|------|
| AccessKey/SecretKey | **绝不收集** | 指导客户使用RAM角色 |
| TLS私钥 | **绝不收集** | 仅收集证书过期时间 |
| 应用密码 | **绝不收集** | 使用Secret引用名称替代 |
| Pod日志 | 脱敏后收集 | 过滤密码、Token等 |
| 节点主机名 | 可收集 | 用于定位 |
| 内网IP | 可收集 | 仅用于诊断 |

## 6. 常见问题快速参考

| 问题分类 | 远程首条指令 | 关键检查点 |
|----------|-------------|-----------|
| Pod无法启动 | `kubectl describe pod <pod>` | Events、资源限制、镜像拉取 |
| 网络不通 | `kubectl run debug --image=busybox -- ping <target>` | CNI、安全组、DNS |
| 存储挂载失败 | `kubectl describe pvc <pvc>` | CSI事件、后端存储状态 |
| 节点NotReady | `kubectl describe node <node>` | Kubelet状态、磁盘压力 |
| 证书过期 | `kubeadm certs check-expiration` | apiserver、etcd证书 |
| DNS解析异常 | `kubectl logs -n kube-system -l k8s-app=kube-dns` | CoreDNS配置、上游DNS |
| 负载均衡异常 | `aliyun slb DescribeHealthStatus` | 后端健康、监听配置 |
| 集群升级失败 | `aliyun cs GET /clusters/<id>/upgrade_status` | 前置检查、版本兼容性 |
