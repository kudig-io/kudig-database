# 阿里云存储集成

本文档覆盖阿里云专有云 ACK 集群的存储方案：OSS CSI、NAS CSI、云盘 CSI（ESSD/SSD/SAS）以及本地盘 LVM 管理。面向远程顾问场景，提供配置示例、排查流程和常见问题处理。

---

## 1. OSS CSI驱动

### 1.1 静态 Provision

静态 Provision 适用于已存在的 OSS Bucket，通过 Secret 和 PV/PVC 关联：

```yaml
# OSS静态PV
apiVersion: v1
kind: Secret
metadata:
  name: oss-secret
  namespace: default
type: csi.storage.k8s.io/secret
data:
  akId: <base64-ak-id>
  akSecret: <base64-ak-secret>
---
apiVersion: v1
kind: PersistentVolume
metadata:
  name: oss-static-pv
spec:
  capacity:
    storage: 5Gi
  accessModes: ["ReadWriteMany"]
  persistentVolumeReclaimPolicy: Retain
  csi:
    driver: ossplugin.csi.alibabacloud.com
    volumeHandle: oss-static-pv
    volumeAttributes:
      bucket: "apsara-prod-bucket"
      url: "oss-cn-apsara-local.aliyuncs.com"
      otherOpts: "-o max_stat_cache_size=0 -o allow_other"
      path: "/data/oss"
    nodePublishSecretRef:
      name: oss-secret
      namespace: default
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: oss-static-pvc
  namespace: default
spec:
  accessModes: ["ReadWriteMany"]
  resources:
    requests:
      storage: 5Gi
  volumeName: oss-static-pv
  storageClassName: ""
```

### 1.2 动态 Provision

动态 Provision 通过 StorageClass 按需创建 OSS Bucket 子目录：

```yaml
# OSS StorageClass
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: oss-dynamic
provisioner: ossplugin.csi.alibabacloud.com
parameters:
  bucket: "apsara-prod-bucket"
  url: "oss-cn-apsara-local.aliyuncs.com"
  csi.storage.k8s.io/provisioner-secret-name: "oss-secret"
  csi.storage.k8s.io/node-publish-secret-namespace: "kube-system"
reclaimPolicy: Delete
volumeBindingMode: Immediate
mountOptions:
  - "-o max_stat_cache_size=0"
  - "-o allow_other"
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: oss-dynamic-pvc
spec:
  accessModes: ["ReadWriteMany"]
  storageClassName: oss-dynamic
  resources:
    requests:
      storage: 10Gi
```

### 1.3 OSS 挂载参数

| 参数 | 说明 |
|------|------|
| `-o max_stat_cache_size=0` | 禁用stat缓存 |
| `-o allow_other` | 允许其他用户访问 |
| `-o umask=000` | 全权限开放 |

> ⚠️ **🟡 中危变更** — 变更集群资源状态，建议先 --dry-run 或 diff 确认
> - `kubectl exec`：进入容器执行命令，可能改变容器状态

``` bash
# 🟡 中风险：会修改集群/资源状态，执行前请确认目标、影响范围与授权
# OSS挂载检查
kubectl get pv,pvc | grep oss
kubectl exec -it <pod> -- df -h | grep oss
ps aux | grep ossfs
```
### 1.4 OSS 远程诊断

``` bash
# 🟢 低风险：只读/信息收集，通常无副作用
# OSS远程诊断
kubectl get pods -n kube-system | grep oss
kubectl logs -n kube-system -l app=csi-ossplugin --tail=200
kubectl get pv,pvc | grep oss
kubectl describe pvc oss-static-pvc
```

## 2. NAS CSI驱动

### 2.1 NAS 静态 Provision

```yaml
# NAS静态PV
apiVersion: v1
kind: PersistentVolume
metadata:
  name: nas-static-pv
  labels:
    alicloud-pvname: nas-static-pv
spec:
  capacity:
    storage: 100Gi
  accessModes: ["ReadWriteMany"]
  persistentVolumeReclaimPolicy: Retain
  csi:
    driver: nasplugin.csi.alibabacloud.com
    volumeHandle: nas-static-pv
    volumeAttributes:
      server: "nas-apsara-prod.cn-apsara-local.nas.aliyuncs.com"
      path: "/share/k8s-data"
      vers: "3"
      options: "nolock,tcp,noresvport"
    mountOptions:
      - "nolock"
      - "tcp"
      - "noresvport"
      - "rsize=1048576"
      - "wsize=1048576"
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: nas-static-pvc
spec:
  accessModes: ["ReadWriteMany"]
  resources:
    requests:
      storage: 100Gi
  selector:
    matchLabels:
      alicloud-pvname: nas-static-pv
```

### 2.2 NAS 动态 Provision

```yaml
# NAS StorageClass
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: nas-dynamic
provisioner: nasplugin.csi.alibabacloud.com
parameters:
  server: "nas-apsara-prod.cn-apsara-local.nas.aliyuncs.com"
  path: "/share"
  vers: "3"
  options: "nolock,tcp,noresvport"
  volumeAs: "subpath"
reclaimPolicy: Delete
volumeBindingMode: Immediate
mountOptions:
  - "nolock"
  - "tcp"
  - "noresvport"
  - "rsize=1048576"
  - "wsize=1048576"
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: nas-dynamic-pvc
spec:
  accessModes: ["ReadWriteMany"]
  storageClassName: nas-dynamic
  resources:
    requests:
      storage: 50Gi
```

### 2.3 NFS v3 vs v4 选择

| 特性 | NFS v3 | NFS v4 |
|------|--------|--------|
| 有状态/无状态 | 无状态 | 有状态 |
| 锁机制 | NLM（网络锁管理器） | 内置锁 |
| 防火墙友好 | 需要多个端口 | 单一端口2049 |
| 性能 | 小文件读写更优 | 大文件顺序读写更优 |
| 兼容性 | 更广泛 | 需确认客户端支持 |
| 推荐场景 | 通用业务 | 大数据/AI训练 |

```yaml
# NFS v4 PV
apiVersion: v1
kind: PersistentVolume
metadata:
  name: nas-nfs4-pv
spec:
  capacity:
    storage: 200Gi
  accessModes: ["ReadWriteMany"]
  csi:
    driver: nasplugin.csi.alibabacloud.com
    volumeHandle: nas-nfs4-pv
    volumeAttributes:
      server: "nas-apsara-prod.cn-apsara-local.nas.aliyuncs.com"
      path: "/share/nfs4"
      vers: "4.0"
      options: "noresvport"
    mountOptions:
      - "noresvport"
      - "rsize=1048576"
```

## 3. 云盘CSI驱动

### 3.1 StorageClass 配置

```yaml
# ESSD PL1 StorageClass（专有云推荐）
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: alicloud-disk-essd-pl1
provisioner: diskplugin.csi.alibabacloud.com
parameters:
  regionId: "cn-apsara-local"
  zoneId: "cn-apsara-local-a"
  diskCategory: "cloud_essd"
  performanceLevel: "PL1"
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
allowVolumeExpansion: true
---
# SSD 云盘 StorageClass
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: alicloud-disk-ssd
provisioner: diskplugin.csi.alibabacloud.com
parameters:
  diskCategory: "cloud_ssd"
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
allowVolumeExpansion: true
```

### 3.2 云盘类型对比

| 类型 | IOPS | 吞吐量 | 时延 | 适用场景 |
|------|------|--------|------|----------|
| ESSD PL3 | 100万 | 4GB/s | 0.1ms | 金融核心 |
| ESSD PL1 | 5万 | 350MB/s | 0.3ms | 通用生产 |
| SSD | 2.5万 | 300MB/s | 0.5ms | 通用业务 |
| SAS | 5000 | 140MB/s | 1ms | 冷数据/备份 |

### 3.3 PVC 与 StatefulSet 使用

```yaml
# StatefulSet 使用云盘
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql
  replicas: 3
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
        - name: mysql
          image: mysql:8.0
          volumeMounts:
            - name: data
              mountPath: /var/lib/mysql
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: ["ReadWriteOnce"]
        storageClassName: alicloud-disk-essd-pl1
        resources:
          requests:
            storage: 500Gi
```

### 3.4 云盘扩容

> ⚠️ **🟡 中危变更** — 变更集群资源状态，建议先 --dry-run 或 diff 确认
> - `kubectl edit/patch`：修改运行中的资源
> - `kubectl exec`：进入容器执行命令，可能改变容器状态

``` bash
# 🟡 中风险：会修改集群/资源状态，执行前请确认目标、影响范围与授权
# 修改PVC并扩容文件系统
kubectl patch pvc db-data-pvc -p '{"spec":{"resources":{"requests":{"storage":"1000Gi"}}}}'
kubectl exec -it mysql-0 -- resize2fs /dev/vdb
kubectl exec -it mysql-0 -- df -h /var/lib/mysql
```
### 3.5 云盘快照

```yaml
# VolumeSnapshotClass
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshotClass
metadata:
  name: alicloud-disk-snapshot
driver: diskplugin.csi.alibabacloud.com
parameters:
  forceDelete: "true"
deletionPolicy: Delete
---
# 创建快照
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshot
metadata:
  name: mysql-data-snapshot
spec:
  volumeSnapshotClassName: alicloud-disk-snapshot
  source:
    persistentVolumeClaimName: db-data-pvc
```

## 4. 本地盘和LVM

```yaml
# 本地盘PV
apiVersion: v1
kind: PersistentVolume
metadata:
  name: local-disk-pv
spec:
  capacity:
    storage: 1788Gi
  accessModes: ["ReadWriteOnce"]
  persistentVolumeReclaimPolicy: Retain
  local:
    path: /mnt/local-disk
  nodeAffinity:
    required:
      nodeSelectorTerms:
        - matchExpressions:
            - key: kubernetes.io/hostname
              operator: In
              values:
                - cn-apsara-node-1
```

### 4.2 LVM 管理

```bash
# 节点LVM操作
pvs; pvcreate /dev/vdb /dev/vdc
vgcreate vg-k8s /dev/vdb /dev/vdc
lvcreate -L 500G -n lv-data vg-k8s
mkfs.ext4 /dev/vg-k8s/lv-data
mkdir -p /mnt/k8s-data
mount /dev/vg-k8s/lv-data /mnt/k8s-data
echo '/dev/vg-k8s/lv-data /mnt/k8s-data ext4 defaults 0 0' >> /etc/fstab
lvextend -L +200G /dev/vg-k8s/lv-data
resize2fs /dev/vg-k8s/lv-data
```

### 4.3 本地存储方案对比

| 方案 | 动态供给 | 扩容 | 适用场景 |
|------|----------|------|----------|
| 裸本地盘 | 否 | 否 | 临时缓存 |
| LVM + static PV | 否 | 手动 | 本地数据库 |
| TopoLVM | 是 | 是 | 云原生本地存储 |
| [[entities/openebs.md|OpenEBS]] LocalPV | 是 | 否 | 开源替代方案 |

## 6. 远程诊断流程

### 6.1 存储问题通用排查

``` bash
# 🟢 低风险：只读/信息收集，通常无副作用
#!/bin/bash
# 存储远程诊断脚本

echo "=== CSI 组件 ==="
kubectl get pods -n kube-system | grep csi
kubectl get sc

echo "=== PVC/PV ==="
kubectl get pvc -A
kubectl get pv

echo "=== 异常事件 ==="
kubectl get events --field-selector reason=FailedMount --sort-by='.lastTimestamp' | tail -20

echo "=== CSI 日志 ==="
kubectl logs -n kube-system -l app=csi-plugin --tail=100

echo "=== 节点磁盘压力 ==="
kubectl get nodes -o custom-columns=NAME:.metadata.name,DISK_PRESSURE:.status.conditions[?(@.type=="DiskPressure")].status
```
### 6.2 常见问题速查

| 症状 | 根因 | 远程处理 |
|------|------|----------|
| PVC 一直 Pending | StorageClass不存在/参数错误 | 检查SC配置、provisioner运行状态 |
| FailedMount | 节点无法挂载/后端不可用 | 检查节点磁盘、NAS/OSS可达性 |
| 云盘无法Attach | 节点在同一AZ无库存 | 确认volumeBindingMode为WaitForFirstConsumer |
| OSS挂载后文件不可见 | 缓存问题 | 重启Pod或调整ossfs参数 |
| NAS读写慢 | 网络/协议问题 | 检查NFS版本、rsize/wsize参数 |
| 本地盘数据丢失 | 节点问题 | 确认应用有副本机制、使用云盘替代 |
| LVM扩展失败 | VG空间不足 | 添加PV或清理LV |
| 快照创建失败 | CSI快照控制器异常 | 检查snapshot-controller Pod |
| 扩容后文件系统未扩展 | 未执行resize | 指导客户在Pod内执行resize2fs |
