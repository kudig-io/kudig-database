# 数字人发布会视频 — 制作方案与提示词

> **总时长**: 15 分钟
> **风格**: 科技发布会 (类 Apple WWDC / KubeCon Keynote)
> **数字人形象**: 男性/女性技术演讲者, 深色正装, 简洁背景

---

## 一、制作平台选型

| 平台 | 适用场景 | 数字人质量 | 中文支持 | 价格 |

## 二、数字人形象设定

### 形象 A: 技术专家型 (推荐)

```
性别: 男性
年龄: 30-35 岁
着装: 深灰色圆领衫 + 深色外套 (类 Steve Jobs / Sam Altman 风格)
```

### 形象 B: 产品讲解型

```
性别: 女性
年龄: 28-32 岁
着装: 白色衬衫 + 深色西装外套
```

## 三、视频分段制作指南

### 段落 1: 开场 Hook (0:00 - 1:00)

**数字人提示词 (HeyGen Script)**:

```
你是一个 K8s 运维工程师。每天凌晨 3 点, 你被电话叫醒:
"集群出问题了, Pod 全在重启。"

你打开电脑, 看到满屏的 CrashLoopBackOff。
你开始翻文档、搜 Google、问同事。
2 小时后, 你发现只是一个环境变量写错了。

2 小时。一个环境变量。

如果有一个 AI 智能体, 它读过 3,346 篇 K8s 生产运维文档,
能在 30 秒内告诉你根因呢?

今天, 我们发布 kudig-database。
```

**画面设计**:
- 0:00-0:15: 数字人正面, 深色背景, 讲述故事
- 0:15-0:30: 画面右侧叠加终端截图 (CrashLoopBackOff 输出)
- 0:30-0:45: 画面切换为搜索动画 (Google → 文档 → Stack Overflow)
- 0:45-1:00: 画面渐变为 kudig-database logo + "3,346 篇" 大字

**AI 视频生成提示词 (Runway/Pika)**:

```
Scene 1: A tired engineer sitting at a desk at 3am, laptop screen

Scene 3: Split screen showing Google search, documentation pages,
Stack Overflow, all being scanned rapidly, tech interface style
```

### 段落 2: 产品介绍 (1:00 - 3:00)

**数字人提示词**:

```
kudig-database 是什么?

一句话: 它是 3,346 篇 K8s 生产运维知识的结构化语料库,
专门为 AI 智能体设计。

40 个知识域。从控制平面到网络, 从存储到安全, 从可观测到 AI 基础设施。
97 个行业场景。从电商到金融, 从医疗到 IoT, 从自动驾驶到量子计算。
218 个 CNCF 项目。从 graduated 到 sandbox, 全覆盖。

[停顿]

但数量不是重点。

重点是: 每一篇文档都有标准的元数据,
每一个故障树都有完整的推理链,
每一个运维技能都有可执行的脚本。

这不是一堆 Markdown 文件。这是一个为 AI 而生的知识引擎。
```

**画面设计**:
- 1:00-1:30: 数字人 + 右侧数据飞入动画 (3,346 / 40 / 97 / 218)
- 1:30-2:00: 知识域全景图展开 (40 个节点的网络图)
- 2:00-2:30: 行业场景图标矩阵 (97 个图标网格)
- 2:30-3:00: 对比动画 "普通文档 vs 结构化语料" (YAML front matter 示例)

### 段落 3: 六大模式演示 (3:00 - 10:00)

#### 模式 1: 深度研究 (3:00 - 4:30)

**数字人提示词**:

```
第一个模式: 深度研究。

假设你刚接手 K8s 集群的 etcd 运维。
你对 etcd 一无所知, 但老板要求你一周内成为专家。

你只需要问一句话:

"我要深度研究 etcd 的生产运维, 包括架构原理、Raft 共识、备份恢复和性能调优。"

[停顿, 展示 Agent 输出]

Agent 命中了 domain-01-cluster-fundamentals 的 etcd 深度文档。
1,042 行。从 Raft 协议到 MVCC 数据模型, 从 Watch 机制到备份恢复。
30 分钟的系统性知识, 30 秒输出。

这相当于一个资深 SRE 花 3 天整理的知识体系。
```

**画面**: 屏幕录制 Agent 实时输出 (或预录制的屏幕动画)

#### 模式 2: 问题排查 (4:30 - 6:00)

**数字人提示词**:

```
第二个模式: 问题排查。

线上出问题了。Pod 一直在重启, RESTARTS 数字不断增长。
你慌了。

别慌。问 Agent:

"线上 Pod CrashLoopBackOff, RESTARTS 一直在涨, 帮我排查。"

[停顿, 展示 Agent 输出]

Agent 直接调用了诊断脚本。
它检查了上次崩溃日志, 排除了 OOM 问题,
发现是 livenessProbe 超时设置过短。

从发现问题到定位根因, 不到 1 分钟。
而且 Agent 给出的不是泛泛的建议, 是可执行的命令。
```

#### 模式 3: 架构设计 (6:00 - 7:30)

**数字人提示词**:

```
第三个模式: 架构设计。

老板让你设计一套金融支付系统的 K8s 架构。
要满足 PCI-DSS 合规要求。
你怎么做? 翻文档? 找参考? 花一周写方案?

问 Agent:

"帮我设计一套金融支付系统的 [[entities/kubernetes|kubernetes]] 生产架构, 要满足 PCI-DSS 合规要求。"

[停顿, 展示 Agent 输出]

Agent 给出了完整的微服务拆分、安全架构、多可用区部署方案,
还有多云对照表——阿里云、AWS、GCP、Azure 的对应服务映射。

这份方案可以直接拿去做技术评审。
```

#### 模式 4: 命令解读 (7:30 - 8:30)

**数字人提示词**:

```
第四个模式: 命令解读。

看到一个报错, 不确定什么意思。

"kubectl describe pod 显示 OOMKilled, Exit Code 137。"

Agent 直接告诉你:
137 等于 128 加 9, 即被 SIGKILL 信号终止。
容器内存超限, 被内核 OOM Killer 强制杀掉。

对于新手, 一个 Exit Code 137 可能要查半天。
Agent 秒级解读。
```

#### 模式 5+6: 速查 + 学习 (8:30 - 10:00)

**数字人提示词**:

```
还有两种模式。

速查参考: "PromQL 查 CPU 使用率怎么写?" 秒级返回。
学习路径: "我是 K8s 新手, 给我一个 4 周学习计划。" 个性化输出。

六种模式, 覆盖从新手到专家的全部场景。
```

## 四、后期制作指引

### 字幕

```
字体: 思源黑体 / Noto Sans SC
字号: 主字幕 48px, 副标题 64px
颜色: 白色, 关键词青色高亮 (#00E5FF)
位置: 画面下方 1/5 处
```

### 转场

```
段落间: 深色渐变过渡 (0.5s)
数据展示: 数字飞入动画
对比画面: 左右分屏滑入
```

### BGM

```
开场 (0:00-1:00): 低沉紧张弦乐 (营造痛点感)
产品介绍 (1:00-3:00): 轻快科技电子乐
演示 (3:00-10:00): 背景轻音乐, 不抢注意力
数据愿景 (10:00-13:00): 渐强史诗配乐
CTA (13:00-15:00): 明亮积极收尾曲

推荐曲库: Artlist / Epidemic Sound 搜索 "tech keynote" "innovation"
```

### 分辨率

```
主视频: 1920x1080 (16:9)
短视频切片: 1080x1920 (9:16) 竖版
封面图: 1920x1080 + 1080x1080 两版
```

## 五、短视频切片 (6 个, 各 30-60 秒)

从 15 分钟主视频中剪辑 6 个短视频, 用于抖音/视频号/B站/小红书:

| # | 标题 | 时长 | 内容 |
|---|------|------|------|
| 1 | "凌晨 3 点被叫醒排查 K8s 问题" | 30s | 开场痛点故事 |
| 2 | "30 秒成为 etcd 专家" | 45s | 深度研究演示 |
| 3 | "1 分钟定位 Pod CrashLoop 根因" | 45s | 问题排查演示 |
| 4 | "5 分钟设计金融 K8s 架构" | 60s | 架构设计演示 |
| 5 | "Exit Code 137 是什么意思" | 30s | 命令解读演示 |
| 6 | "3,346 篇 K8s 知识, 开源免费" | 30s | 数据 + CTA |

每个切片的开头 3 秒必须有强 Hook (问题/冲突/数据冲击)。
