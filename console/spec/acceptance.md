# Console 验收标准与度量

> 结构型产品的验收不能只看"页面能打开"。本文给出**三个层次**的验收：数据正确性（可自动校验）、视图正确性（可脚本断言）、体验有效性（需人测）。

## 1. 第一层：数据正确性（CI 自动）

| 编号 | 检查项 | 方法 | 通过标准 |
|------|--------|------|----------|
| D1 | 派生物与仓库同步 | `make console-check` | 0 个 STALE |
| D2 | 锚点存在 | 遍历 `triples.json`，读源文件对应行 | 100% 命中且非空 |
| D3 | 章节归属 | `sectionIndex` 对应的 H2 在 `blocks.json` 中存在 | 100% |
| D4 | 词表合法性 | 所有 `entity` / `dimension` 在受控词表中 | 100% |
| D5 | 引用完整性 | 视图引用的每个结构 id 可在 `blocks.json` 找到 | 0 个悬空 |
| D6 | 体积阈值 | `blocks.json` ≤ 40MB，`triples.json` ≤ 15MB | 通过 |

**D2 是本项目的生命线**：可回溯率跌破 100% 时，整批结构视图不得发布。

## 2. 第二层：视图正确性（脚本断言）

### 2.1 每个视图必须有断言

| 视图 | 断言 | 实测基线（2026-11-10） |
|------|------|------------------------|
| 构成剖面 | 4 个分区的段宽之和 = 4,815 | core 1,529 · supporting 1,947 · peripheral 1,131 · reference 23 · 未标注 185 |
| 拆解树 | 打开 `17-mysql-kubernetes-production-guide` 后节点数 = H2+H3 数 | H2 8 · H3 8 |
| 一致性热力 | `07` 域 4 个产品页的 7 个维度态与实测一致 | 备份 4/4 · 监控 4/4 · 高可用 3/4 · 故障转移 3/4 · 连接池 3/4 · 性能 2/4 · 扩缩容 1/4 |
| 热力层级标记 | 每格必须标注 `H2` / `H3` / `提及` | 「备份」在 07 域 H2 = 0、H3 = 4/4，两者不可混同 |
| 对比矩阵 | 不出现跨 `group` 的实体对 | 全部同组 |
| 关系邻域 | 默认中心 = 入链最高页；跳数 ≤ 2 | `Kubernetes`(1,648) |
| 演化时间线 | 月份数 = 有日期的月份数 | 8 个月；`2026-05` 2,410 页 · `2026-07` 1,476 页 |

### 2.2 反向断言（防止"看起来对"）

- **空必须空**：对比矩阵中语料未写的格，断言其 `data-state="absent"`，不得出现任何文字（包括"无"）。
- **不跨域借数据**：热力中某域缺维度时，断言该格不引用其他域的值。
- **不聚合冒充明细**：若视图做了聚合，断言标题包含"已聚合"。

## 3. 第三层：体验有效性（人测，3 个真实场景）

| 场景 | 任务 | 计时起点 | 计时终点 | 目标 |
|------|------|----------|----------|------|
| S1 选型 | "MySQL 与 TiDB 在备份和高可用上差在哪？" | 打开工作台 | 说出对照结论 | ≤ 5 分钟 |
| S2 排障 | "Pod CrashLoopBackOff 该走哪条路径？" | 打开工作台 | 打开第一个可执行技能卡 | ≤ 90 秒 |
| S3 体感 | "这套语料的强项和三个缺口是什么？" | 打开工作台 | 说出 1 强项 + 3 缺口 | ≤ 3 分钟 |

每场景记三项：**是否完成 / 用时 / 走了几个视图**（越少越好，> 3 个视图视为导航失败）。

## 4. 持续度量

| 指标 | 定义 | 采集方式 | 目标 |
|------|------|----------|------|
| 结构覆盖率 | 能进入至少一个结构视图的页占比 | 派生数据统计 | ≥ 85% |
| 可回溯率 | 锚点命中比例（D2） | CI | 100% |
| 视图利用率 | 各视图的访问占比 | 前端埋点（可选） | 主视图（构成/热力/矩阵）≥ 70% |
| 抽屉展开率 | 点击结构元素后打开抽屉的比例 | 埋点 | ≥ 40%（低于说明元素不可点或不可信） |
| 定位原文率 | 抽屉中"定位原文"点击率 | 埋点 | ≥ 20%（说明结构结论确实值得下钻验证） |

## 5. 发布门禁

结构视图发布前必须同时满足：

1. CI 六项数据检查全绿；
2. 该视图的脚本断言全绿；
3. 至少 3 次人工抽检（每次 20 条锚点）100% 一致；
4. 视觉审阅：在 1440 / 1024 / 390 三档截图确认无溢出、无遮挡、无颜色误用。

## 6. 回归策略

- **数据层**：每次 `console-sync` 后运行 D1–D6；
- **视图层**：每个视图一份断言脚本，改渲染逻辑必须同步改断言；
- **视觉层**：三档截图归档到 `.impeccable/review/`，与上一版对比。

## 7. 已知不可自动化项

- 维度词表"是否合理"（需人工）；
- 对比矩阵摘要"是否有用"（需人测场景）；
- 邻域图"是否读得懂"（需用户测试）。
