# KUDIG Console PRD v2

> **一句话定位**：Console 不是知识库的阅读器，而是**知识库结构的分析台**——在读者打开任何一篇文章之前，先用图表告诉他这片知识的构成、关系、一致性与演化；原文只作为"证据页"下钻。

## 1. 背景与问题

### 1.1 现状

仓库已有 4,815 个内容页、2,277 张 Mermaid 图、123,028 行表格（口径见 `console/README.md`）。`console/` 第一版（v1）已能逐页阅读并在正文里渲染图，但它服务的是"读"，不是"看结构"。

### 1.2 真实痛点（均来自语料实测，非假设）

| # | 痛点 | 证据 | 后果 |
|---|------|------|------|
| P1 | 读者不知道从哪进 | 1,450 页无任何库内入链；6 个 ≥5 页的域没有入口页 | 搜索是唯一入口，用户放弃 |
| P2 | 不知道该读多深 | 七层落锁：0 层 1,414 页（29%）、≤3 层 3,896 页（81%）、七层齐备仅 20 页 | 打开十篇八篇是半成品，信任下降 |
| P3 | 同一维度散落在多页 | `07 数据库中间件` 70 页里，"监控告警"作为编号小节出现 6 次、"故障排查速查"10 次，各写各的 | 选型/对照要靠人肉拼 |
| P4 | 图找不到 | 844 页有图，但 109 页占了大半；1,055 页纯文字 | 想看结构得逐页翻 |
| P5 | 知识偏斜不可见 | 同域内产品页的维度覆盖 3–4/4，其余页面接近 0 | 决策者以为覆盖均匀 |

### 1.3 非目标

- 不做通用搜索引擎（保留现有精确搜索作为兜底）。
- 不做 LLM 自动摘要/知识图谱生成（易幻觉，且无法逐条回溯）。
- 不做全库力导向关系图（4,815 节点既不可读也不可交互）。

## 2. 目标用户与场景

| 用户 | 真实场景 | 成功定义 |
|------|----------|----------|
| **决策者**（SRE Lead / 架构师） | "这套语料值不值得作为团队基座？哪里薄？" | 5 分钟内能说出强项与三处缺口 |
| **选型工程师** | "MySQL 和 TiDB 在备份上差在哪？" | 只靠对比矩阵做出判断，不必读满 70 页 |
| **值班 SRE** | "Pod CrashLoop，去哪条路径？" | 结构视图直达故障树与技能卡 |
| **体系维护者** | "下一批该补哪一域哪一层？" | 缺口清单可直接变成任务 |
| **AI Agent / RAG 工程** | "哪些页面是可引用的结构化证据？" | 结构视图可作为语料质量门 |

## 3. 信息架构：四层 + 六个结构视图

```
L1 全库形状     构成剖面 · 演化时间线
L2 域内结构     一致性热力 · 拆解树
L3 跨页对照     对比矩阵 · 关系邻域
L4 证据         阅读页（终态，不承担导航）
```

| 视图 | 层级 | 回答 | 主数据源 |
|------|:----:|------|----------|
| 构成剖面 | L1 | 由什么组成 | `index.json` (tier/part/域/层) |
| 演化时间线 | L1 | 怎么长出来的 | `index.json` (date) |
| 一致性热力 | L2 | 哪里一致、哪里缺 | `blocks.json` (H2 维度) |
| 拆解树 | L2 | 一页/一域拆成几段 | `blocks.json` |
| 对比矩阵 | L3 | 同维度跨页对照 | `blocks.json` (表格 + 维度) |
| 关系邻域 | L3 | 读完去读哪 | `index.json` (`out`) + `nodes.json` |

## 4. 功能需求

### 4.1 F1 构成剖面

- **描述**：每个分区/域一条堆叠条，段 = tier（core/supporting/reference/peripheral/未标注）；悬停显示页数与七层均值。
- **验收**：4 个分区、86 个域全部可渲染；点击某段 → 该域页列表按该 tier 过滤。
- **数据**：`structure.tiers` + 每域 tier 分布（需生成器补 `domainTier`）。

### 4.2 F2 拆解树

- **描述**：以选中页/域为根，展开为 `章 → 节 → 表/图/命令行数` 的横树；每个叶子可点开证据。
- **验收**：任意页可展开；叶子必须带"原页锚点"（H2 序号），不可回溯的节点不得出现。
- **数据**：`blocks.json` 首次落地的视图。

### 4.3 F3 一致性热力

- **描述**：行 = 域（或产品），列 = 受控维度（高可用/备份/监控/故障转移/连接池/存储/扩缩容/慢查询…），格值 ∈ {专节, 提及, 无}。
- **验收**：`07 数据库中间件` 中 4 个产品页的维度覆盖必须与实测一致（备份 4/4、监控 4/4、高可用 3/4、故障转移 3/4、连接池 3/4、慢查询 2/4、扩缩容 1/4）。
- **数据**：`dimensions.json` + `blocks.json`。

### 4.4 F4 对比矩阵

- **描述**：选定"实体组"（如 4 个数据库产品）× 维度组（如 3 个运维维度），生成矩阵；每格显示摘要 + 证据链接。
- **验收**：矩阵每格可点到原页的小节；空单元格显示为琥珀虚线（= 语料确实没写），不补内容。
- **数据**：`blocks.json` 表格抽取 + 实体归一。

### 4.5 F5 关系邻域

- **描述**：以选中页为中心展开 2 跳邻域；半径 = log(入链)，颜色 = 分区。
- **验收**：默认中心为全网入链最高的页（当前 Kubernetes 1,648）；展开不超过 2 跳；任一节点可点开证据。
- **数据**：`index.json` 的 `out` 与 `in`。

### 4.6 F6 演化时间线

- **描述**：按 `last_updated` 月份堆叠柱（按层分组）；叠加某域的层演变标尺。
- **验收**：能识别"同月大批 0–2 层薄页"的批次特征。
- **数据**：`index.json` (date, layers)。

### 4.7 F7 阅读页（降级为证据页）

- 保留现有渲染能力（图原位、表格、代码折叠），**移除其导航职责**：不再承担入口与目录树。
- 从任一结构元素进入时，页面需高亮"你是从哪个结构元素来的"。

## 5. 数据契约

### 5.1 新增抽取层

| 层 | 文件 | 内容 | 可回溯字段 |
|----|------|------|-----------|
| 块级 | `data/blocks.json` | 每页 `sections[]`：`h2`/`h3` 标题、序号、行区间、表格数、代码块数 | `page`, `h2Index`, `lineStart` |
| 实体级 | `data/entities.json` | 实体（产品/组件）词典与同义词归一 | `aliases`, `canonical` |
| 维度级 | `data/dimensions.json` | 受控维度词表（中文维度 → 匹配规则） | `pattern`, `dimension` |
| 关系级 | `data/triples.json` | `{page, entity, dimension, sectionAnchor, evidenceLines}` | 每条三元组必须带锚点 |

### 5.2 硬性规则

1. **无锚点不成图**：任何出现在结构视图里的结论，必须能定位到 `page + h2Index + lineStart`。
2. **空即空**：语料没写就显示"无"，禁止用同域其他页的数据补齐。
3. **抽取可重跑**：所有派生数据由 `make console-sync` 重建，CI 用 `make console-check` 阻断漂移。
4. **词表受控**：实体与维度只能来自 `entities.json` / `dimensions.json`，新增需人工审。

## 6. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 首屏 < 2s；任一切换视图 < 500ms；单页证据抽屉 < 300ms |
| 体积 | 首屏 JS+CSS < 300KB（不含 Mermaid）；结构索引按视图懒加载 |
| 可访问性 | 全键盘可达；图表带文本等价（表格视图）；≥4.5:1 对比度 |
| 离线 | 零 CDN；Mermaid 本地引擎；字体系统栈 |
| 可维护 | 生成器单文件、纯标准库；派生数据不接受手工编辑 |

## 7. 分期与里程碑

| 期 | 范围 | 退出标准 |
|----|------|----------|
| M0 | 文档冻结（本 PRD + 设计规范 + 数据契约） | 评审通过 |
| M1 | `blocks.json` + 拆解树 + 构成剖面 | 86 域全部可拆；证据可回溯 100% |
| M2 | 维度词表 + 一致性热力 | 07 域热力与实测一致 |
| M3 | 对比矩阵 | 3 个真实选型场景可 5 分钟内完成 |
| M4 | 关系邻域 + 演化时间线 | 邻域 2 跳可用；时间线可识别薄页批次 |

## 8. 度量

| 指标 | 定义 | 目标 |
|------|------|------|
| 结构覆盖率 | 能被至少一个结构视图表达的页面占比 | ≥ 85% |
| 可回溯率 | 结构结论可落到原页小节的占比 | 100% |
| 对照可用性 | 3 个场景 5 分钟完成判断 | 3/3 |
| 视图非重复度 | 同一结论只在 1 个视图出现 | 100% |

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 维度词表覆盖不足 | 热力/矩阵大量空白 | M2 前用 07 域做词表验收；不足则先小范围上线 |
| 标题不规范（同义异写） | 对齐失败 | 归一规则 + 人工抽检 10%；不一致的单列"未归类" |
| 结构视图过多导致认知负担 | 用户迷路 | 主舞台只留 3 个（构成、热力、矩阵），其余进"更多" |
| 派生数据膨胀 | 仓库变大 | `blocks.json` 只存锚点与计数，不存正文 |

## 10. 开放问题

1. 维度词表由谁维护、多久审一次？
2. 是否允许"跨域对齐"（如把 `19-故障诊断` 的故障类与 `07` 的故障节对比）？
3. AI Agent 是否可以直接消费 `triples.json` 而不读原文——需要约定引用格式。
