# 维度词表与标注作业规范

> 维度是结构视图的"列"。列定义错，后面所有格子都是错的。本文规定**词表怎么建、怎么标、怎么验**，并给出实测基线。

---

## 1. 为什么需要受控词表

语料里同一件事有多种写法（`故障排查` / `故障与 remediation` / `常见故障`），而不同产品对同一能力的叫法又不一样（`故障转移` / `节点替换`）。不做归组，热力与矩阵都无法跨页比较；归组过头，又会把不同能力混为一谈。

**原则**：词表是**受控的、有版本的、可回溯的**；每次变更都记录新增/合并/删除及理由。

---

## 2. 词表结构

```json
{
  "schema": "kudig-console-dimensions/1",
  "version": "2026.11.1",
  "dimensions": [
    { "id": "d-backup", "name": "备份恢复", "group": "data-lifecycle", "class": "operation",
      "patterns": ["备份", "恢复", "pitr", "wal-g", "xtrabackup", "br "],
      "matchLevel": ["h2", "h3"] }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 稳定 id，发布后不改名（视图与 URL 依赖） |
| `name` | 展示名（中文） |
| `group` | 维度组：矩阵按组对齐（`data-lifecycle` / `observability` / `availability` / `performance` / `capacity` / `architecture`） |
| `class` | `layer`（对应七层）或 `operation`（跨层运维维度） |
| `patterns` | 匹配片段（小写、去空格） |
| `matchLevel` | 允许的命中层级：`h2` / `h3` / 两者 |

## 4. 实测基线（用于回归）

### 4.1 07 域基线（`make prototype-verify` 的回归三行）

数据库中间件家族（P2 重编号后为 `06-存储与数据/08~16` 九个子域，66 个非索引页；原 `07 数据库中间件` 基线沿用），按"H2 或 H3 命中"统计：

| 维度 | 命中页 | 占比 | 基线值 | 容差 |
|---|---:|---:|---:|:---:|
| 监控告警 | 39 | 58.2% | 0.63 | ±0.15 |
| 备份恢复 | 29 | 43.3% | 0.45 | ±0.15 |
| 高可用 | 18 | 26.9% | 0.32 | ±0.15 |

> 基线值来自上一版（12 维词表 + 仅 H2/H3 逻辑）的实测；扩到 21 维后个别页会被更靠前的维度先"认领"，所以留 ±15 个百分点容差。超出即视为回归。

## 5. 标注作业流程

```
① 抽样（每域 10 页）
     ↓
② 人工标"这一节讲的是哪个维度"（可多选，可标"无"）
     ↓
③ 与机器抽取结果比对，产出混淆矩阵
     ↓
④ 针对误判调词表（加/删 patterns、调整 matchLevel）
     ↓
⑤ 重复 ②–④ 直到准确率 ≥ 90%
     ↓
⑥ 冻结版本号，全量重跑
```

### 5.1 判定口径

| 情况 | 判为 | 例 |
|---|---|---|
| 有独立小节（H2/H3）且 ≥3 行 | 专节 | `4.3 备份` |
| 正文段落提到但无小节 | 提及 | "建议开启自动备份" |
| 小节名不同但内容等价 | 专节 + `mappingNote` | `5.3 TiKV 节点替换` ⇒ 高可用 |
| 仅同义词出现在别的语境 | 不判 | "恢复到出厂设置" |

### 5.2 争议处理

- 两人标注不一致 → 第三人裁决，并把案例写入 `cases/`；
- 词表无法表达的新维度 → 先加 `unclassified`，在月度评审决定是否新建维度。

---

## 6. 质量控制指标

| 指标 | 定义 | 门槛 |
|---|---|---|
| 标注一致性（Kappa） | 两标记者间的一致性 | ≥ 0.75 |
| 精确率 | 机器标为某维度的节中，人认为正确的比例 | ≥ 0.90 |
| 召回率 | 人标为某维度的节中，机器找回的比例 | ≥ 0.80 |
| 未分类率 | 无法归入任何维度的节占比 | ≤ 15% |

---

## 7. 词表演化规则

1. **新增**：需在 ≥2 个域中出现 ≥3 次，且有明确的区分边界；
2. **合并**：仅当两维度的标注 Kappa > 0.8（人为不可区分）时合并；
3. **删除**：连续两版全库命中 < 5 页，标记 `deprecated`，保留 id 一年；
4. 所有变更写入本文 §3 并递增 `version`。
