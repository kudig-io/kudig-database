# 琐事消除（Toil Elimination）

> Toil 是 SRE 术语，指与生产服务运行相关、但手工重复且可被自动化的低价值劳动。琐事不等于"不喜欢的工作"——它有严格的判定标准。

## 1. 琐事的六项判定标准

同时满足越多，越应优先自动化：

1. **手工执行**：需要人敲命令、点页面
2. **重复出现**：同类操作反复发生
3. **可自动化**：机器可以替代人完成
4. **战术性**：中断驱动、被动响应，而非主动规划
5. **无持久价值**：做完后系统状态没有长期改善
6. **随规模线性增长**：集群/服务数量翻倍，工作量随之翻倍

反例：一次性的架构设计、复盘写作、容量评估属于工程工作（Engineering），不是琐事。

## 3. 治理流程

```
度量 → 归类 → 排序 → 自动化 → 验证
 │                                │
 └── 琐事占比 > 50% 触发红线 ──────┘
```

1. **度量**：值班日志/工单系统打标，统计每类操作的频次 × 耗时
2. **排序**：按"节省小时数 ÷ 自动化成本"排定优先级
3. **自动化分级**：脚本化 → 半自动（人审批+机执行）→ 全自动（含回滚护栏）
4. **验证**：自动化上线后跟踪该类琐事归零，且未引入新故障模式

## 4. 常见陷阱

- 🔴 **自动化放大故障**：无护栏的批量操作会把单点失误放大到全集群，自动化必须内置限流、金丝雀与熔断
- 🟡 **自动化本身成为琐事**：脆弱脚本需要持续人工看护，应按软件工程标准（测试、版本、监控）维护自动化资产
- 🟡 **只自动化不消除根因**：频繁重启的服务应修复内存泄漏，而非把重启做成定时任务
