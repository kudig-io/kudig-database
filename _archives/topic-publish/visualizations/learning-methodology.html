Core Engine

循环引擎：写 · 读 · 问 · 改

以语料仓库为核心枢纽，通过四个互相驱动的环节构成闭环学习引擎。Agent 在每个环节中承担不同角色，推动知识的持续生长与演进。

✎

写 — 创作语料

Write & Create

通过 AI Agent 创作、编写和更新技术文档与语料库。每一次写作都是对知识的结构化表达，将隐性知识转化为可检索、可复用的显性资产。

AGENT 行为：根据模板生成技术文档、更新 README 索引、补充缺失知识点、创作排查指南与最佳实践文档
K8s 安全加固指南GPU 调度策略文档硬件故障排查手册
📖

读 — 系统研读

Read & Absorb

系统化阅读技术文档、规范标准和实战案例。从底层硬件到上层应用，构建跨层次、跨领域的完整知识图谱。

AGENT 行为：检索语料仓库、定位知识缺口、推荐关联文档、辅助构建跨域知识连接与依赖关系图
CIS BenchmarkLinux 内核文档NVMe 协议规范
❓

问 — 提问探索

Ask & Explore

通过精准提问和探索性对话深化概念理解。Agent 作为对话伙伴，引导从表面认知走向深层洞察与跨域关联发现。

AGENT 行为：回答技术问题、解释复杂概念、提供多角度分析、生成诊断思路与解决方案
Pod 为何不应以 root 运行？NUMA 如何影响 GPU 调度？
🔄

改 — 迭代改进

Iterate & Improve

基于反馈不断优化语料质量和知识覆盖度。每次循环都让知识体系更准确、更完整、更深入，形成螺旋上升的演进轨迹。

AGENT 行为：审校已有文档、补充新发现、修正过时内容、优化文档结构与可读性、合并重复知识
K8s 1.32 API 变更更新新 CVE 安全补丁纳入

Design Principles

方法论设计原则

六条核心设计原则支撑循环学习方法论的有效运转，确保系统的可持续性与自适应能力。

PRINCIPLE 01

输出倒逼输入

先写再读。写作暴露认知空白，驱动精准的目标式学习。创作语料本身就是最高效的深度学习行为。

PRINCIPLE 02

问题驱动深度

好的问题比好的答案更重要。每一个技术问题都是深入某个领域的入口，提问能力决定学习上限。

PRINCIPLE 03

迭代胜于完美

不追求一步到位的完美文档。通过持续的小步迭代，让知识从 v0.1 演进到 v1.0。发布比完美更重要。

PRINCIPLE 04

跨域连接思维

真正的洞察产生于领域的交叉地带。刻意在 K8s、AI、Linux、硬件、安全之间建立知识桥梁。

PRINCIPLE 05

Agent 即同事

AI Agent 不是工具，而是协作伙伴。赋予 Agent 明确的角色与职责，像管理团队一样管理 Agent 矩阵。

PRINCIPLE 06

语料即资产

结构化的语料库是可复用的知识资产。每篇文档都是对组织知识的投资，随时间推移产生复利效应。
