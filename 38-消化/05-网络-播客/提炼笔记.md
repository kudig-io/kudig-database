## 板块一：K8s 网络模型三原则（来源：00-总览/01、01-K8s网络核心/00、03）

- **一句话定位**：K8s 网络的基石是三条铁律 + CNI 插件落地。
- **核心观点**：
  1. 三大规则：所有 Pod 可直接通信（无 NAT）；节点与 Pod 可直接通信；Pod 看到的自己的 IP 就是别人看到的 IP（扁平化网络）。
  2. 同节点 Pod 通信走 veth pair + Linux Bridge（cbr0），无封装；跨节点靠 CNI 的封装（VXLAN）或路由（BGP/host-gw）或 eBPF。
  3. CNI 是规范不是产品：kubelet 在 Pod 创建时调用 `/opt/cni/bin` 下的插件二进制，传 `CNI_COMMAND=ADD/DEL`。
- **关键技术点**：Network Namespace（每个 Pod 的"网络小黑屋"）、veth pair（虚拟网线）、iptables DNAT/SNAT"变脸术"、IPAM 地址管理。

## 板块二：CNI 插件选型（来源：01-K8s网络核心/04、03）

- **一句话定位**：五大主流 CNI 的性能与选型对照。
- **核心观点**：
  1. 性能排序（吞吐量/延迟）：Terway ENIIP 最优（VPC 直通）；Cilium 与 Calico eBPF 模式"很高/低延迟"；Flannel VXLAN 居中。
  2. 选型口诀：通用生产选 Calico（成熟稳定）；高性能/安全选 Cilium（eBPF 原生、L7 策略）；简单场景选 Flannel；阿里云选 Terway；多集群选 Cilium ClusterMesh。
  3. 封装方式决定开销：Flannel 用 VXLAN，Calico 可 IPIP 或纯 BGP 路由，Cilium 可全程 eBPF 免 iptables。
- **关键技术点**：VXLAN 封装 vs BGP 路由模式；Calico IPPool；Cilium Hubble 可观测。

## 板块三：Service、DNS 与 kube-proxy（来源：00-总览/01）

- **一句话定位**：虚拟 IP 背后的转发机制与性能拐点。
- **核心观点**：
  1. iptables 模式规则匹配是 O(n)，Service 超过 1000 个时延迟明显；IPVS 是 O(1) 哈希查找，大规模集群必选。
  2. CoreDNS 解析链：Pod 的 resolv.conf 由 kubelet 注入，`ndots:5` 会导致大量无效 search 查询，生产建议降到 2。
  3. eBPF（Cilium）替代 iptables 全链路可降低延迟 30-50%；NodeLocal DNSCache 可减轻 CoreDNS 压力。
- **关键技术点**：KUBE-SVC/KUBE-SEP 规则链、ipvsadm、topologyAwareHints 就近路由。

## 板块四：东西向与南北向——服务网格 vs API 网关（来源：03-服务网格/07、04-API网关/01、02）

- **一句话定位**：微服务流量治理的两条战线与新一代标准 Gateway API。
- **核心观点**：
  1. 服务网格管东西向（服务间）流量：Istio 功能最全但重，Linkerd 轻量，Consul Connect 绑定 Consul 生态，Dapr 是分布式运行时路线，Traefik Mesh 极简；Istio Ambient Mesh 用 ztunnel 取消 Sidecar，显著降低每 Pod 资源开销。
  2. API 网关管南北向（外部进入）流量：Ingress 靠注解表达高级能力、可移植性差；Gateway API 用 GatewayClass/Gateway/HTTPRoute 三层角色模型分离平台与业务职责。
  3. Gateway API 时间线：v1.0（2023-10）HTTPRoute GA，v1.1 引入 GRPCRoute 与 BackendTLSPolicy，v1.2（2024-11）开始实验性支持 Mesh 场景（GAMMA）。
- **关键技术点**：mTLS 零信任、流量分割金丝雀、请求镜像、TLS Passthrough。

## 板块五：eBPF 与 Cilium——内核里的网络革命（来源：05-eBPF/01、03、06、07）

- **一句话定位**：不改内核源码就能在内核里安全跑沙箱程序，重写网络与安全栈。
- **核心观点**：
  1. eBPF 本质是内核中的虚拟机：程序经验证器（verifier）校验后 JIT 执行，挂在 XDP/TC/kprobe 等挂载点，用 Map 存取状态。
  2. Cilium 是 CNCF 毕业项目，架构 = 每节点 Agent DaemonSet + 集群级 Operator + CNI 插件，用 eBPF 替代 iptables 实现转发、NetworkPolicy 与 L7 策略。
  3. 配套生态：Tetragon 做运行时安全（进程/文件/网络行为感知），Hubble 做网络可观测。
- **关键技术点**：cBPF 只做包过滤 → eBPF 通用可编程；Helper 函数白名单；BPF Map 类型。

## 板块六：Terway——阿里云 VPC 原生 CNI（来源：06-Terway/01、02、07）

- **一句话定位**：让 Pod 直接拿到 VPC 身份，性能与云上安全组/策略打通。
- **核心观点**：
  1. Terway 是阿里云 ACK 自研 CNI，核心目标是 Pod 直接接入 VPC，与 VPC 网络策略、安全组保持一致。
  2. 五种数据面模式：VPC 路由（无封装、兼容性好）、ENI 独占（性能最高但 Pod 密度受 ENI 配额限制）、ENIIP（推荐，直通+中高 Pod 密度）、ENIIP-Trunking（Serverless 高密度，需内核 4.19+）、IPVlan（绕过 veth，高性能计算场景）。
  3. 性能表里 Terway ENIIP 吞吐"最高"、延迟与 CPU 开销"最低"——前提是吃透 ECS 实例的 ENI 配额限制。
- **关键技术点**：Terway DaemonSet + Controller 控制面、eni-config ConfigMap、ECS 实例规格 ENI 配额速查。
